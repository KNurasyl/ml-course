# M12: настоящая малая языковая модель и адаптер

Цель: увидеть изменение вероятностей следующего символа при обучении и проверить регрессию после адаптации. Это **биграммная языковая модель**, а не разговорная LLM. Она рассматривает только предыдущий символ и не понимает инструкций.

## Запуск

```powershell
Set-Location C:\projects\ml-llm-course
.\.venv\Scripts\python.exe labs\M12\demo.py
```

Проверено: Windows, Python 3.11.9, PyTorch 2.15.0+cpu. Требуется установленное окружение курса; GPU и сеть при запуске не нужны. Данные генерируются самим кодом, скачивание не требуется. Всего 25 базовых и 10 адаптерных параметров; расчёт использует один CPU-поток. Время процесса на контрольном запуске — около 8 секунд, включая импорт PyTorch; это наблюдение, а не обещание для другого компьютера. Память определяется главным образом Python/PyTorch, а не крошечными весами.

## Что делает код

1. Формирует строки `ab` разной длины; полные строки train/test различаются.
2. Обучает таблицу логитов переходов между пятью символами.
3. Замораживает базу и обучает добавку ранга 1 на новой грамматике `ac`.
4. Проверяет обе грамматики и побитовое сохранение исходных весов.
5. Сохраняет `artifacts/M12/metrics.json` и `tiny-lm.pt`.

Контрольный результат seed=17: исходная loss 1,60944; база на старой задаче 0,16638; база на новой 3,73176; адаптер на новой 0,56625; адаптер на старой 11,98950. Незначительная численная вариативность допустима. Автоматические assertions требуют улучшения базовой задачи, улучшения новой после адаптации и неизменности базы. **Они намеренно не требуют отсутствия регрессии**: сильное ухудшение старой задачи — предмет анализа.

## Самостоятельное изменение

Скопируй исходник в `submissions/M12-HW01/`, добавь обучение на смеси грамматик и сравни обе потери. Не меняй test после просмотра результатов. Объясни неизбежную неоднозначность перехода `a→b` или `a→c` для модели без дополнительного контекста.

Генерация данных — авторский синтетический пример курса. Он проверяет механизм обучения, не качество реальных интервью. Сохранённый checkpoint содержит тензоры и алфавит; загружай только собственные доверенные артефакты.

## Дополнение версии 1.2.0: LoRA через PEFT и DPO через TRL (T44, уроки M12-L08X и M12-L09X)

```powershell
.\.venv\Scripts\python.exe labs\M12\lora_peft.py report
.\.venv\Scripts\python.exe labs\M12\dpo_trl.py report
.\.venv\Scripts\python.exe -m pytest -q tests\test_lora_dpo.py
.\.venv\Scripts\python.exe -m pip install -r requirements-optional.in
.\.venv\Scripts\python.exe labs\M12\lora_peft.py run
.\.venv\Scripts\python.exe labs\M12\dpo_trl.py run
```

`report` и тесты работают без модели и без PEFT и TRL: отчёты читают замороженные прогоны из `quality/lora` и `quality/dpo`. Для `run` нужны пакеты `peft` и `trl` из `requirements-optional.in` и локальная SmolLM2 из M09. Сохранённый результат M12-L07 (`quality/measurements-1.1.0/M12-sft-report.json`) лабораторные только читают и с ним сравнивают.

`labs/M12/lora_peft.py` переносит ручной адаптер M12-L07 на PEFT `LoraConfig`: ранг 4, alpha 8, Q и V четырёх последних блоков. Лабораторная проверяет паритет логитов на одинаковых весах и повторяет прогон M12-L07 с того же старта. Адаптер сохраняется с id и ревизией базы, затем загружается в свежую базу, выключается и сливается, и каждый шаг сверяется по логитам. Записанная до прогона гипотеза `wide` ставит LoRA на все Linear всех 30 блоков.

`labs/M12/dpo_trl.py` обучает DPO через TRL поверх того же SFT. Двенадцать пар собраны из train M12-L07: выбрана ожидаемая команда, отвергнута другая. SFT-адаптер сливается с базой и становится опорной моделью, а TRL обучает поверх новый LoRA-адаптер. Отчёт сравнивает точность на четырёх отложенных парах, вероятность первого токена, check и old NLL и свободные генерации. Флаг `--loss sigmoid sft` добавляет SFT-слагаемое для задачи M12-L09X-A.

Авторский прогон 07.11.2026. PEFT повторил M12-L07 точно: на паритете разница логитов 0.0, потери и генерации совпали, файл весов — 125 КБ. Гипотеза `wide` (1 221 120 параметров) не подтвердилась: команды остались неверными, old NLL вырос с 2.351 до 10.734. История потерь показала, что адаптер запоминает последний блок из шести примеров одного класса. DPO поднял точность на отложенных парах с 0.50 до 1.00, но неверными остались те же 2 команды из 4: первым токеном на расплывчатый ответ по-прежнему идёт NEXT (0.70 против 0.04). С SFT-слагаемым все команды стали верными, но старые вопросы остались сломанными.
