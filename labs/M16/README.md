# M16: приёмочные свидетельства и реальный продукт

Лабораторный скрипт проверяет структуру двух синтетических примеров обратной связи и наличие отчётов прошлых модулей. Он **не проводит пользовательский пилот** и не выставляет общую оценку качеству модели.

```powershell
Set-Location C:\projects\ml-llm-course
.\.venv\Scripts\python.exe labs\M16\demo.py
```

Python 3.11.9, стандартная библиотека, CPU. Ожидаются `fixture_cases_valid=2`, `mixed_rubric_rejected=true`. В `artifacts/M16/` сохраняются отчёт и примеры рубрик. Поля доступности M12–M15 отражают реальные файлы на диске: отсутствие отчёта не превращается в успех. Статус `participant_pilot` остаётся `not performed by this lab`.

## Обязательное продолжение: весь продукт

```powershell
.\.venv\Scripts\python.exe tools\download_models.py --speech --llm
.\.venv\Scripts\python.exe -m projects.interview_trainer.app
```

Открой http://127.0.0.1:8765 в Edge. Полные условия, версии моделей и ограничения находятся в [README эталона](../../projects/interview_trainer/README.md). Выполни HR и backend интервью, текстовую и голосовую реплики, исправление расшифровки, остановку воспроизведения и экспорт собственной сессии. После проверки останови сервер Ctrl+C. Если порт занят, используй `--port 8766`, не завершая неизвестные процессы.

Проверь отдельно: двойную отправку, пустой ввод, неверный режим, устаревший ход, отсутствие модели и поздний звук после отмены. Для каждого случая сохрани ожидаемое и фактическое поведение. Наличие двух валидных JSON в лабораторной не заменяет эти действия.

Небольшая Qwen в фактической проверке давала неподтверждённые сведения и обрыв на лимите 128 токенов. Это рабочий технический эталон с известными дефектами качества. Самостоятельное улучшение должно измеряться на независимых случаях. Результаты участников и карьерная готовность не возникают автоматически после запуска.
