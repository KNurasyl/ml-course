# M13: версия, контракт, наблюдения и откат

Обязательный путь использует стандартную библиотеку Python. Это воспроизводимый эксперимент внутри процесса, а не имитация измеренной промышленной HTTP-нагрузки.

```powershell
Set-Location C:\projects\ml-llm-course
.\.venv\Scripts\python.exe labs\M13\demo.py
```

Проверено на Python 3.11.9, Windows, CPU. GPU, интернет, Docker и платные сервисы не нужны. Синтетические данные определены в исходнике. Результат появляется обычно менее чем за секунду; объём данных — несколько килобайт.

## Ожидаемое поведение

- `active_release` равен `1.0`.
- `bad_release_detected` и `behavior_restored` равны `true`.
- Отклонены четыре невалидных запроса, записаны 100 длительностей.
- В `artifacts/M13/` сохранены два манифеста, JSONL запросов и итоговый отчёт.

Стабильный релиз вычисляет `2*x+1`; ошибочный — `20*x+1`. Canary проверяет три известные точки. После обнаружения ошибки активный объект возвращается к стабильной версии, затем поведение проверяется ещё раз. Задержки `p50_ms`/`p95_ms` измерены для вызова функции и не характеризуют сеть, очередь или много пользователей. Определение p95 — nearest-rank.

Для самопроверки открой JSONL, вычисли квантиль самостоятельно и сравни. Суммы кода изменятся при редактировании исходника: это ожидаемо. Хеш данных фиксирует их канонические байты, но не является оценкой качества.

## Дополнительный Docker

Файл `Dockerfile` демонстрирует упаковку только этого чистого Python-примера. Он не включает Windows SAPI и полный голосовой проект. Если Docker уже установлен, из корня курса можно выполнить:

```powershell
docker build -f labs/M13/Dockerfile -t ml-course-m13 .
docker run --rm ml-course-m13
```

Контейнерный вариант не входит в обязательную проверку на этом ноутбуке: Docker-сборка здесь не заявляется выполненной. Для строгой фиксации образа после получения проверенного digest укажи его вместо изменяемого тега и сохрани в своём отчёте. Отсутствие Docker не мешает пройти модуль.

## Дополнение версии 1.2.0: трассировка LLM-конвейера (T39, урок M13-L07X)

```powershell
.\.venv\Scripts\python.exe labs\M13\tracing.py analyze
.\.venv\Scripts\python.exe -m pytest -q tests\test_tracing.py
```

Обязательный путь — стандартная библиотека Python, без Docker, коллектора и новых пакетов. `analyze` читает замороженные трассы из `quality/tracing` и работает без моделей. Он печатает p50 и p95 по этапам (nearest rank, как в M13-L04), долю спана `chat`, prefill и decode по данным сервера, разрыв между временем клиента и сервера, разбивку по вердиктам проверок и трассу с ошибкой.

`collect` собирает трассы заново и требует llama.cpp и GGUF из M09-L07X. Конвейер M11-L07X отвечает на 66 вопросов, на каждый пишется одна трасса из четырёх спанов: `invoke_workflow rag-answer`, `retrieval`, `chat qwen2.5-0.5b-instruct-q4_k_m`, `evaluate`. Затем один запрос идёт с клиентским дедлайном 50 мс, а следом тот же вопрос без дедлайна. Имена атрибутов — по семантическим конвенциям OpenTelemetry GenAI (коммит e6658f1 репозитория `semantic-conventions-genai`, статус Development). Вердикты шести проверок M11-L07X пишутся событиями `gen_ai.evaluation.result` в `events.jsonl`. Prompt и ответы по умолчанию не записываются; флаг `--capture-content` включает их. Лог сервера остаётся в `artifacts/M13/tracing`.

Во время сбора не запускай ничего тяжёлого: время спанов отражает нагрузку на процессор. Первый авторский прогон шёл одновременно с тестами: ответы те же, но decode в медиане — 20 токенов в секунду против 54 в чистом прогоне. Он сохранён в `quality/tracing-noisy` как отрицательный результат; `analyze --folder quality/tracing-noisy` показывает разницу.

`otlp` переводит трассы в OTLP/JSON (`otlp-traces.jsonl`, `otlp-logs.jsonl` в `artifacts/M13/tracing`). `send --endpoint URL` отправляет их на любой приёмник OTLP по HTTP, например в Langfuse; заголовки авторизации берутся из `OTEL_EXPORTER_OTLP_HEADERS` и не печатаются. Оба шага необязательны, а Langfuse через Docker автор не проверял.

Авторский прогон 06.11.2026: 68 трасс, 271 спан, 402 события. Спан `chat` — 0.999 времени корня; p50 корня 1761 мс, p95 3265 мс. Prefill — 1425 мс в медиане, decode — 283 мс. Брошенный по дедлайну запрос держал слот сервера 1.7 с, и следующий запрос ждал: его разрыв «клиент минус сервер» — 1640 мс при обычных 8 мс. Цена спана — 10.5 мкс. Тесты — `tests/test_tracing.py`.
