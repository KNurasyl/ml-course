# M09 — реальная компактная LLM локально

Обязательная модель: `HuggingFaceTB/SmolLM2-135M-Instruct`, ревизия `12fd25f77366fa6b3b4b768ec3050bf629380bac`, [официальная карточка](https://huggingface.co/HuggingFaceTB/SmolLM2-135M-Instruct), лицензия Apache2.0. Карточка и provenance сохраняются рядом с файлами. Модель преимущественно английская; качество русского интервью не заявлено.

В подготовленной папке веса уже скачаны. Обычный запуск полностью локален:

```powershell
Set-Location C:\projects\ml-llm-course
.\.venv\Scripts\python.exe labs\M09\demo.py
```

Для воспроизведения после удаления папки `models/smollm2-135m-instruct` скачай закреплённые файлы из официального Hub:

```powershell
.\.venv\Scripts\python.exe labs\M09\demo.py --download
```

Первое скачивание требует сети, но не платного API и не аккаунта. Авторский набор файлов занимал 272444345 байт. Обычный запуск использует `local_files_only=True` и не подгружает другую ревизию. Нужны CPU, несколько свободных GB RAM и около 300MB на файлы модели; GPU не используется. При загрузке float32 сами параметры занимают 538060032 байта, но полный процесс требует больше памяти.

Проверено: Python3.11.9, torch2.15.0+cpu, transformers4.57.6, huggingface-hub0.36.2. Используется настоящий `AutoModelForCausalLM`, float32, eager attention,2CPU-потока. Этот первый запуск использует float32. Следующий обязательный опыт benchmark.py действительно сравнивает float32 и dynamic int8; численный пример урока объясняет механизм перед этим сравнением.

Ожидаемые инварианты:134515008 параметров, ненулевой вывод, `context_limit=8192`, вход плюс резерв не превышает лимит. Для основного запроса авторский prompt занимал 31 токен, генерация 21 токен. Один наблюдавшийся запуск: загрузка≈2.59 с, полный generate≈2.23 с. Это замер конкретного окружения, не SLO и не TTFT; текущая нагрузка изменит время.

Фактический ответ был кратким, но круговым определением SQL transaction. На запрос JSON модель выдала Python-код. Валидатор вернул `invalid_json`, `fallback_used=true`. Такой результат является успешной проверкой обработки отказа, а не успешной оценкой кандидата. Не заменяй исходный output эталоном, чтобы сделать отчёт красивее.

`artifacts/M09/report.json` содержит реальные ответы, фактический шаблон, числа токенов, ревизию и времена. После запуска вручную оцени содержание. Для новых экспериментов сохраняй отдельные отчёты. Проверка схемы отвергает пустой feedback, boolean вместо целого score и неверный JSON; синтаксическая корректность сама по себе не подтверждает технические факты.

## Дополнение версии 1.1.0

Полный исполняемый ключ домашней работы открывай после своей попытки:

```powershell
.\.venv\Scripts\python.exe labs\M09\experiments.py
.\.venv\Scripts\python.exe labs\M09\benchmark.py
```

Первая команда выполняет 25 реальных попыток greedy/sampling и сохраняет каждый ответ. Невалидный JSON приводит к конечному ответу `needs_review`, без выдуманной оценки. Вторая команда сравнивает float32 и int8 в отдельных процессах на трёх одинаковых запросах. В Windows измеряется RSS дерева worker-процесса с интервалом 30 мс; сумма RSS может повторно учитывать общие страницы.

Весь опыт использует уже скачанные веса. Рекомендуется около 3 GB свободной RAM сверх других задач; модель использует два CPU-потока. psutil входит в зафиксированное окружение. Int8 не гарантирует ускорения или меньшего RSS: решение принимается по измерениям и содержанию ответов.

Результаты: `artifacts/M09/experiments.json` и `artifacts/M09/benchmark/comparison.json`. Прочитай фактические ответы по рубрике; синтаксический успех не подтверждает их истинность.

## Дополнение версии 1.2.0: локальный serving через llama.cpp (T30, урок M09-L07X)

```powershell
.\.venv\Scripts\python.exe labs\M09\llama_local.py fetch
.\.venv\Scripts\python.exe tools\download_models.py --gguf
.\.venv\Scripts\python.exe labs\M09\llama_serving.py
```

`llama_local.py fetch` скачивает CPU-сборку llama.cpp b11803 для Windows x64 (21.10.2026, 24 МБ) с GitHub, сверяет SHA-256 и распаковывает её в `runtime/llama.cpp/` (папка в `.gitignore`); в систему ничего не ставится. `tools/download_models.py --gguf` скачивает три GGUF с закреплёнными ревизиями и сверяет SHA-256. Это Qwen2.5-0.5B-Instruct Q4_K_M и Q8_0 (официальные файлы Qwen, Apache-2.0) и Qwen3.5-4B Q4_K_M (квантизация unsloth, Apache-2.0; официального GGUF нет, источник выбран автором). `llama_serving.py` сравнивает четыре конфигурации: модель курса в transformers float32 в отдельном процессе и три GGUF в `llama-server` на 127.0.0.1:18080. Условия у всех одинаковые: 4 потока, шесть запросов, жадная генерация, до 64 токенов, контекст 4096. Для Qwen3.5 режим размышлений выключается полем `chat_template_kwargs`. Замеряется:
- TTFT по потоку событий и скорость prefill и генерации из `timings`;
- RSS и private-память процесса с опросом каждые 30 мс;
- состав GGUF по типам тензоров (`gguf_summary`);
- кэш общего начала prompt на запросе, которого сервер ещё не видел.

В замерах `cache_prompt` выключен. Отчёт — `artifacts/M09/llama/report.json`, журнал сервера — рядом. `--only` выбирает конфигурации, `--threads` меняет число потоков. Отсутствующая модель отмечается `not_downloaded`, бинарник — `llama_cpp_missing`. `llama_local.py serve <gguf>` держит сервер в терминале для ручных запросов. Если сервер остался после прерванного запуска, лабораторная откажется стартовать с подсказкой `Stop-Process -Name llama-server`. Тесты — `tests/test_llama_serving.py`.

Авторский прогон 06.11.2026 (Intel Core i7-11800H, около 6 минут). Генерация, токенов в секунду: float32 5.5, Q8_0 18.6, Q4_K_M 24.2, 4B 3.4. TTFT 476, 400, 388 и 1540 мс. Пик RSS / private: 3196 / 5391, 642 / 205, 544 / 234 и 4893 / 2769 МиБ. В первом полном прогоне генерация была медленнее на 3–35 %, тексты ответов совпали. Q4_K_M модели 0.5B — в среднем 6.16 бита на вес, 62 % весов в Q5_0: строки длиной 896 не делятся на 256. У 4B — 5.19 бита, 58 % в Q4_K. Ни один ответ GGUF-версий 0.5B не совпал с float32 слово в слово. Ollama в курсе разобрана обзорно, без установки (решение автора).
