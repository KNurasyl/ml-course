# M07 — настоящая нейросеть на CPU

```powershell
Set-Location C:\projects\ml-llm-course
.\.venv\Scripts\python.exe labs\M07\demo.py
.\.venv\Scripts\python.exe labs\M07\demo.py --verify
```

Проверено: Python 3.11.9, PyTorch 2.15.0+cpu, NumPy 2.4.6, scikit-learn 1.9.1. Точные зависимости входят в общий файл окружения курса. GPU и сеть не используются; вычисления идут одним CPU-потоком на 1000 синтетических объектах `make_moons`. Веса сети занимают сотни чисел; основная память относится к Python, Torch и sklearn. Для комфортного запуска достаточно нескольких свободных GB, на ноутбуке курса работа проверена. Не запускай одновременно несколько тяжёлых моделей.

Данные генерируются локально с seed17 и noise0.20. Разделение:600train,200validation,200test. StandardScaler обучается только на train. MLP `2→16→2` обучается240эпох; лучший checkpoint выбирается по validation. LogisticRegression использует тот же split. Код сохраняет веса, конфигурацию, scaler, split и историю в `artifacts/M07/`.

На проверенном запуске: `best_epoch=110`, `mlp_test_accuracy≈0.975`, `logistic_test_accuracy=0.835`, первый train loss≈0.57927, последний≈0.08726. Это наблюдение конкретного seed и окружения, не обещание преимущества нейросетей. Содержательные проверки требуют снижения loss и test accuracy выше0.8, а не побитового совпадения всех метрик между платформами.

Отдельный Python-процесс восстанавливает комплект и проверяет logits: `fresh_process_max_abs_error=0.0` в авторском запуске, допустимый порог меньше1e−6. Ручной градиент из урока даёт `gradient_w=-8`, `gradient_b=-4`. Проверка только классов была бы слабее: разные logits могут давать одинаковый argmax.

Самостоятельный вариант:

```powershell
.\.venv\Scripts\python.exe labs\M07\demo.py --seed 23 --noise 0.30
```

Артефакты M07 будут заменены результатами этого запуска, поэтому скопируй нужный отчёт в свою папку submissions до эксперимента. Проанализируй две ошибки, не предполагая заранее конкретной accuracy. `--verify` относится к последнему сохранённому комплекту.
