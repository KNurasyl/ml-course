## M12-L01-A

**Условие:** Разбери три случая: модель нарушает JSON в восьми из двадцати ответов; правильно цитирует старый документ вместо нового; выдаёт одинаково общую обратную связь для разных ответов кандидатов. Для каждого предложи первый эксперимент, метрику и основание перейти к более дорогому вмешательству. Не используй название технологии вместо объяснения причины.

**Обоснованное решение:** Формат: сначала явная схема, пример и проверка парсером; считать валидность и содержательную точность отдельно. Старый факт: проверить версии корпуса и retrieval, затем подставить свежий фрагмент вручную; измерять правильность версии и подтверждение источником. Общая обратная связь: проверить наличие ответа кандидата и рубрики во входе, затем сопоставить конкретность с экспертными примерами. SFT оправдан только при устойчивом остаточном недостатке поведения и независимом улучшении; двадцать ответов позволяют начать диагностику, но не доказать универсальное превосходство.

**Что проверить в своей работе:** результат должен следовать из приведённых входов и принятого контракта. Если использованы другие числа или данные, пересчитай вывод; совпадение формулировки с эталоном не требуется. Критическая ошибка — объявить проверенным то, что не было выполнено. После чтения реши новый вариант из урока и отметь объём помощи.

## M12-L03-A

**Условие:** Скопируй лабораторную в свою рабочую папку и замени базовую грамматику ab на abc. Сохрани пять символов алфавита. До запуска выпиши допустимые переходы и объясни, почему переход c→конец конфликтует с c→a. Затем измерь heldout loss и проверь сохранение и загрузку весов.

**Обоснованное решение:** Переходы: ^→a, a→b, b→c, c→a и c→$. Матрица остаётся 5×5, то есть 25 параметров. Остаточная ошибка возникает из неопределённости завершения; биграммная модель не различает одинаковый c в начале и конце строки.

## M12-L02-B-C

B: перенос на Q: train={r1,r2}, test={r3,r4}; Q disjoint, авторы S1/S2 присутствуют в обеих частях намеренно. Перенос на автора: train={r1,r3}, test={r2,r4}; S disjoint, Q1/Q2 присутствуют в обеих частях намеренно. Для одновременного переноса допустим train={r1}, test={r4}, r2/r3 исключены; Q1∩Q2 и S1∩S2 пусты. При требовании использовать все четыре строки в двух непустых частях без обоих пересечений такого split нет: связи Q и S соединяют все строки. Малый размер не позволяет делать широкий вывод о переносе.

Перенести все Q7 в одну часть, а для проверки выбрать другой исходный Q, либо явно изменить цель эксперимента. Target с неподтверждённым достижением исправить на основанный на input ответ или исключить как некачественную разметку с записью причины. ## M12-L03-B-C

B: c встречается четырежды: трижды следующий символ a и один раз EOS. Оптимум эмпирического распределения p(a|c)=3/4, p(EOS|c)=1/4. Средняя потеря на этих четырёх позициях −(3·ln(0.75)+ln(0.25))/4≈0.562335 нат. Один и тот же вход c имеет разные правильные продолжения, поэтому функция только от c не может различить позиции. Не нужно выдавать эту неоднозначность за неудачный optimizer.

C: требуется девять раз продолжить после b, затем остановиться: 0.9**9·0.1≈0.038742, около 3.87%. Это не вероятность любой длины ≤10. Greedy всегда выбирает a, потому что 0.9>0.1, и не выберет EOS без внешнего лимита. Sampling иногда останавливается, но длина случайна. Счётчик повторов или позиция с доступом к истории различает десятую b и более ранние; внешний ограничитель длины тоже задаёт правило, но не доказывает, что bigram выучила счёт.


## M12-L04-B-C

B: W содержит 64 параметра; адаптер 8r+8r=16r. r=3 →48, r=4 →64, r=5 →80. Строгая экономия 16r<64 выполняется для r∈{1,2,3}. r=4 даёт равенство, r=5 превышает исходное число. Это только параметрический счёт данной матрицы; реальная память включает базу, активации, градиенты и состояние optimizer.

C: ΔW=[[0,2],[0,0]], Wx=[0,1]ᵀ, (W+ΔW)x=[2,1]ᵀ. MSE до=0, после=((2−0)**2+(1−1)**2)/2=2. Исходный W не изменился, но эффективное преобразование изменилось. ## M12-L08X-A

Решение обучает тот же адаптер `same` и меняет только порядок примеров. Нужны пакет `peft` и локальная SmolLM2 из M09; на CPU ключ работает около 20 секунд.

```python
import importlib.util
from pathlib import Path

if importlib.util.find_spec("peft") is None or not Path("models/smollm2-135m-instruct/model.safetensors").exists():
    print("нужны пакет peft и локальная SmolLM2 из M09, ключ пропущен")  # optional: requirements-optional.in
    raise SystemExit(0)

import torch
from peft import get_peft_model


def load(name, path):
    spec = importlib.util.spec_from_file_location(name, path)
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    return module


lab, sft, m09 = load("lora_peft", "labs/M12/lora_peft.py"), load("sft", "labs/M12/sft.py"), load("m09", "labs/M09/demo.py")
torch.set_num_threads(2)
torch.manual_seed(lab.SEED)
tokenizer, base, _ = m09.load_local()

lab.init_like_m12(model, lab.SEED)

# the only change: CLARIFY and NEXT alternate instead of six-and-six blocks
order = [i for pair in zip(range(6), range(6, 12)) for i in pair]
train = [sft.masked_example(tokenizer, *sft.TRAIN[i]) for i in order]
check = [sft.masked_example(tokenizer, q, a) for q, a in sft.CHECK]
old = [sft.masked_example(tokenizer, q, a, system="You are a concise assistant.") for q, a in sft.OLD]
before_old = sft.mean_loss(model, old)
lab.train(model, train)
after = lab.stage(sft, tokenizer, model, (train, check, old))
print("check NLL", round(after["check_nll"], 3), "old NLL", round(before_old, 3), "->", round(after["old_nll"], 3))
print("check", [row["actual"] for row in after["check_generations"]])
print("old", [row["actual"] for row in after["old_generations"]])
assert after["task_review"]["critical_wrong_command_indices"] == []  # the command type is right on all four check cases
assert after["old_nll"] > before_old                                 # and the old questions got worse
```

Результат авторского прогона:
- **Тип команды исправился.** Неверных команд на check стало 0 из 4 вместо 2: на расплывчатые ответы модель начинает с CLARIFY. Точное совпадение осталось 0.5: ответ обрывается на «CLARIFY:» без второй части.
- **Check NLL снизился с 0.332 до 0.144.** Чередование не даёт адаптеру запомнить последний блок одного класса.
- **Старые вопросы сломались сильнее.** Old NLL вырос с 2.351 до 2.811, то есть на 19.6%. На «What is 2 plus 2?» модель повторяет «NEXT: Explain: Explain: …», а на просьбу назвать язык выдумывает «CLU».

Правило оказалось слабее, чем нужно: как и предупреждал M12-L07, в защитный набор нужны старые прикладные случаи и чтение ответов, а не только порог old NLL. Выпускать нельзя. Следующая гипотеза — подмешать старые случаи в train или снизить learning rate.

Четыре примера check, по два на класс, не доказывают гипотезу о порядке. Это один прогон с одним seed, и другой порядок, например начиная с NEXT, мог дать другой результат. Гипотезу подтверждают на новом независимом наборе и нескольких seed. Кроме того, check уже использован при выборе гипотезы, поэтому для окончательной проверки нужен новый набор.

Критические ошибки: менять вместе с порядком ещё и learning rate или число шагов; объявить успех по check NLL и не прочитать ответы на старые вопросы; выбирать порядок по результату на том же check и называть check независимым.

## M12-L09X-A

Решение читает замороженный авторский прогон варианта и сравнивает его с основным DPO. Ни модель, ни TRL для этого не нужны. Сам прогон делает команда `.\.venv\Scripts\python.exe labs\M12\dpo_trl.py run --loss sigmoid sft --out artifacts\M12\dpo-sft`, на CPU около полутора минут.

import json

base = json.loads(Path("quality/dpo/report.json").read_text(encoding="utf-8"))
variant = json.loads(Path("quality/dpo/report-sigmoid-sft.json").read_text(encoding="utf-8"))

## M12-L09X-B-C

**B.** Отрыв равен β·(−1.0 − (−3.0)) = 2β. При β = 0.1 отрыв 0.2, потеря ln(1 + e^(−0.2)) ≈ 0.598. При β = 0.5 отрыв 1.0, потеря ≈ 0.313. Для сравнения, ln 2 ≈ 0.693. Точность на парах учитывает только знак отрыва, поэтому пара уже засчитана как верная. Потеря учитывает величину, умноженную на β. При малом β тот же сдвиг стоит мало, и чтобы снизить потерю, модели приходится сдвигать log-вероятности сильнее и дальше уходить от опоры. Поэтому β — это масштаб, в котором сдвиг считается достаточным, а не шаг обучения.

**C.** План пар для русского тренажёра:
- **Источник.** Выбранный ответ — правка интервьюера, отвергнутый — исходный ответ модели. Ещё один источник — оценки двух черновиков на один запрос. Персональные данные кандидатов без согласия не используются.
- **Разнообразие отвергнутых.** На каждый класс ошибок нужно несколько формулировок отвергнутого ответа. Авторский прогон показал, что модель обходит одну запрещённую строку соседней.
- **Баланс и защита.** Классы сбалансированы. Добавлены защитные пары для старого поведения: на общий вопрос выбран обычный ответ, отвергнута команда.
- **Опора.** Опорная модель — текущая SFT, и это проверяется до обучения.
- **Проверка.** Свободная генерация на новом независимом наборе, доля верного первого токена, чтение выборки ответов человеком и регрессия на старых случаях. Точность на парах — только одна из величин.
