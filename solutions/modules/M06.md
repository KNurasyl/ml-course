# M06: решения для самопроверки

Открывай после собственной попытки. Если ты изучил ключ до решения, новая задача из раздела повторения обязательна для проверки самостоятельности. Числа в учебных примерах не являются оценкой реальных кандидатов.

## M06-L01-A

Запуск: 90/100 = 0,90. Завершение среди запущенных: 72/90 = 0,80; среди всех попыток: 72/100 = 0,72. Корректность в проверенной выборке: 24/30 = 0,80. Продуктовая метрика — завершение среди стартовавших; содержательная — доля объяснений, прошедших техническую рубрику; техническая — доля успешных стартов. Цели, например p95 ответа не более выбранного порога и ограничение памяти, требуют измерения времени каждого шага и пикового RSS на заданном ноутбуке. Эти пороги нельзя объявить достигнутыми. Нельзя переносить результат 24/30 на непроверенные ответы без описания способа выборки и неопределённости.

## M06-L02-A

Для C: x=20 → z=0 → −1; x=30 → z=2 → 3. При scale=10 первый ответ остаётся −1, второй становится 1. Поэтому нужны оба контрольных объекта, а не только центр. Manifest: release_id, model_file и его sha256, preprocessing_file и sha256, code_revision, training_data_revision, feature_order, input_schema_version, validation_report. Минимальная проверка: assert predict(20,C)==−1 и assert predict(30,C)==3. Хеши обнаруживают изменение файлов; контрольные значения обнаруживают ошибку применения согласованного формата. Одного названия «latest» недостаточно для воспроизведения.

## M06-L03-A

Начала [0,1,2,4], окончания [1,2,3,5], задержки [1,1.5,2,1]. Embedding базы — batch при публикации новой версии или по расписанию; при просрочке индекс помечается прежней версией. Следующий вопрос — online, потому что зависит от нового ответа; перегрузка даёт понятное ожидание или отказ до принятия запроса. Недельная сводка — batch после закрытия периода; показывается время среза и возможность обновления. Конкретные допустимые сроки — требования продукта, не результат этой арифметики.

## M06-L04-A

A: (18+8)/(20+10)=26/30≈0,867; RU=0,90, EN=0,80. B: 41/50=0,82; RU=0,60, EN≈0,967. Общий спад около4,7 процентного пункта скрывает падение RU на30пунктов и рост EN примерно16,7пункта. Кроме того, состав выборки изменился, поэтому сравнение общих долей смешивает поведение и веса групп. Событие invalid_output с request_id/release_id/schema_version; метрики invalid_output/attempts и p95duration; действие — вернуть валидируемый предыдущий шаблон после проверки и исследовать сохранённые обезличенные ошибки.

## M06-L05-A

Первый S7:3 создаёт обработку или сохранённый ответ. Повтор с тем же содержимым получает тот же результат либо статус in_progress; повтор с другим содержимым под тем же ключом отклоняется как конфликт. Для активного хода3 результат хода2 не принимается:

```python
def accept_result(active_turn, result_turn):
    return active_turn == result_turn
assert accept_result(3,3)
assert not accept_result(3,2)
```

В реальном диалоге дополнительно проверяются session_id и generation_id, поскольку одна реплика может быть перегенерирована. Откат: прекратить выдачу candidate, переключить указатель на stable-комплект, проверить совместимость входной схемы, выполнить контрольные запросы и затем проверить долю ошибок. Успешный процесс без верного контрольного ответа не подтверждает восстановление.

## M06-HW01

Один корректный вариант: synchronous POST /sessions/S/turns с idempotency_key, question_id, answer и schema_version. Ответ содержит turn_id, release_id, status, feedback и evidence_ids. Численный baseline использует releaseA=(mean10,scale2,w3,b1): x14→7. Обучение пишет новую неизменяемую папку; проверка сравнивает метрики и контрольные ответы; current.json переключается только после успешной проверки.

Подготовка embeddings и ночная сводка — batch; следующая реплика — online. Мониторинг: input_invalid/requests, invalid_output/generations, p95latency, качество ручной выборки с размером и версией рубрики. Отказ входа возвращает структурированную ошибку до модели; повтор ключа не создаёт ход; поздний generation_id отбрасывается. Неудачный candidate с mean12 и старым w3 даёт4 вместо7, поэтому возвращается весь releaseA. После отката x14 снова даёт7. Лабораторная demo.py выполняет этот минимальный протокол. Для полноценной модели добавить независимый набор качества: один контрольный вход проверяет целостность, а не обобщение.

Самопроверка: система с HTTP200 и неверным feedback не проходит содержательный критерий; высокие проценты без знаменателя не проходят метрики; откат только файла весов не проходит надёжность. Поддержка AI влияет на отметку самостоятельности, но не изменяет арифметику правильности.
