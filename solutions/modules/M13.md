## M13-L01

**Условие:** Составь манифест для тренажёра, у которого обновился только поисковый корпус. Укажи минимум восемь полей и объясни, какие файлы нужно сохранить для воспроизведения. Затем сравни два JSON с разным порядком ключей и докажи одинаковую каноническую сумму.

**Обоснованное решение:** Нужны release_id, code_commit, model_id и hash весов, tokenizer_id, prompt_hash, corpus_hash, index_hash, retrieval_config, evaluation_version, dependency_lock, created_at. Для восстановления нужны сами документы, индекс или воспроизводимый рецепт его создания, код, конфигурация и доступные локальные веса. Хеш без файла недостаточен. `json.dumps(obj, sort_keys=True, separators=(',', ':'))` обеспечивает одинаковое представление для перестановок ключей одного объекта; оно не превращает два разных типа, например 2 и"2", в одинаковый объект.

**Что проверить в своей работе:** результат должен следовать из приведённых входов и принятого контракта. Если использованы другие числа или данные, пересчитай вывод; совпадение формулировки с эталоном не требуется. Критическая ошибка — объявить проверенным то, что не было выполнено. После чтения реши новый вариант из урока и отметь объём помощи.

## M13-L03

**Обоснованное решение:** Структура: обязательные поля score, evidence, next_step нужных типов. Факт: ответ о транзакции должен различать commit и rollback. Дефект 2: объяснение транзакции верно, однако кандидату приписано знание, которого в его ответе нет. Это показывает, почему корректность общего технического текста не заменяет проверку справедливости персональной обратной связи.

## M13-L04

**Условие:** Для двадцати запросов сохрани total_ms, queue_ms, asr_ms и generation_ms. В учебной таблице пусть у четырёх запросов очередь составляет 900 мс, у остальных 0; ASR200 мс и generation300 мс всегда. Вычисли среднее и p95 общего времени. Предложи проверку причины, которая не сводится к немедленной смене модели.

**Обоснованное решение:** Шестнадцать запросов занимают 500 мс, четыре 1400 мс. Среднее=(16·500+4·1400)/20=680 мс. Nearest-rank p95 — девятнадцатый элемент,1400 мс. Модельная часть постоянна, поэтому сначала проверить конкурентность, длину очереди и политику допуска. Повторить опыт с одним и двумя активными запросами при одинаковых данных, отдельно измеряя ожидание и вычисление. Нельзя утверждать причину только по агрегату; требуется связанный лог или трасса.

**Что проверить в своей работе:** результат должен следовать из приведённых входов и принятого контракта. **Обоснованное решение:** Остановить приём новых тяжёлых запросов; зафиксировать состояние и причину; выбрать манифест A; восстановить соответствующий индекс schema1 из сохранённого снимка; загрузить полный комплект; выполнить canary через API; возобновить приём. Текущие запросы либо завершаются на закреплённой версии, либо явно отменяются с возможностью повторить, без смешивания компонентов. Успех: ответ содержит releaseA и контрольный запрос возвращает ожидаемый документ/результат. Дополнительно проверить сохранность сессий. Если снимка нет, нельзя обещать быстрый откат; требуется восстановление индекса из исходных документов.

## M13-HW01

Сопоставь свою работу с двумя отдельными ключами: [выбор релиза](../exercises/M13/solution.py) и [полный HTTP-эксперимент](../exercises/M13/hw_reference.py). Первый проверяет контракт: все обязательные проверки должны быть именно True и схема совместима. Второй запускает настоящий локальный HTTP-сервер отдельным процессом, сравнивает capacity=2/3 при clients=1/2/4 и отдельно выполняет дедлайн, несовместимый релиз и откат.

```powershell
.\.venv\Scripts\python.exe exercises\M13\check.py solutions\exercises\M13\solution.py --self-test
.\.venv\Scripts\python.exe solutions\exercises\M13\hw_reference.py
```

При capacity=2 одновременно допускаются работающий запрос и один ожидающий; при capacity=3 — работающий и два ожидающих. На четырёх синхронно стартующих клиентах наблюдались соответственно два и один отказ 503. Это результат данного опыта, не универсальная гарантия планировщика ОС. 504 означает истечение дедлайна принятого ожидающего запроса; 503 — отсутствие места до вычисления. queue_ms и compute_ms не складывай повторно с client_ms: клиент уже измеряет весь запрос. Веса y=2x+1 и вычисление 80 мс моделируются, HTTP, очередь и перезапуск реальны.

В artifacts/M13-hw/report.json сохранены все ответы, в artifacts/M13-http/report.json — исходные режимы и проверка восстановления. Несовместимый schema2 отвергается новым процессом; после восстановления манифеста A новый процесс отвечает 15 на x=7. Это две независимые проверки: совместимость при загрузке и поведение через API. Старый процесс не считается восстановленным только из-за смены ссылки active.

После ключа измени только схему индекса при прежних весах. Ожидается отклонение до обслуживания; повторный canary по весам один не обнаружил бы несовместимость. Через неделю восстанови весь комплект по манифесту и проверь версию и ответ новым процессом. Нельзя подменить отсутствующий артефакт одним хешем.
