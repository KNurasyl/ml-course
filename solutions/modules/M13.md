## M13-L07X-A

Решение ниже работает в одном процессе: сервис — поток `http.server`. На настоящую границу процессов оно переносится без изменений, потому что контекст передаётся только заголовком.

```python
import http.server
import importlib.util
import json
import tempfile
import threading
import time
import urllib.request
from pathlib import Path

spec = importlib.util.spec_from_file_location("tracing", "labs/M13/tracing.py")
tracing = importlib.util.module_from_spec(spec)
spec.loader.exec_module(tracing)
folder = Path(tempfile.mkdtemp())
client, service = tracing.Tracer(folder / "client"), tracing.Tracer(folder / "service")
seen = []


def parse(header):
    version, trace_id, span_id, flags = header.split("-")
    assert version == "00" and len(trace_id) == 32 and len(span_id) == 16 and flags == "01"
    return trace_id, span_id


class Handler(http.server.BaseHTTPRequestHandler):
    def do_POST(self):
        seen.append(tracing.CURRENT.get())  # a new thread starts without the caller's context
        header = self.headers.get("traceparent")
        token = None
        if header:
            trace_id, parent_id = parse(header)
            token = tracing.CURRENT.set(tracing.Span(trace_id, parent_id, None, "remote parent", "CLIENT", {}))
        try:
            with service.span("POST /v1/chat/completions", "SERVER", {"http.request.method": "POST"}):
                time.sleep(0.02)  # the model's work
        finally:
            if token:
                tracing.CURRENT.reset(token)
        self.send_response(200)
        self.end_headers()

    def log_message(self, *args):
        pass


server = http.server.HTTPServer(("127.0.0.1", 0), Handler)
threading.Thread(target=server.serve_forever, daemon=True).start()
url = f"http://127.0.0.1:{server.server_port}/v1/chat/completions"
with client.span("invoke_workflow demo", attributes={"gen_ai.operation.name": "invoke_workflow"}):
    with client.span("chat tiny", "CLIENT", {"gen_ai.operation.name": "chat", "gen_ai.provider.name": "llama.cpp"}) as chat:
        request = urllib.request.Request(url, data=b"{}", headers={"traceparent": tracing.traceparent(chat)}, method="POST")
        urllib.request.urlopen(request, timeout=5).read()
    urllib.request.urlopen(urllib.request.Request(url, data=b"{}", method="POST"), timeout=5).read()  # no header
server.shutdown()
client.close()
service.close()

read = lambda name: [json.loads(x) for x in (folder / name / "spans.jsonl").read_text(encoding="utf-8").splitlines()]
chat_span, root = read("client")
served, orphan = read("service")
assert seen == [None, None]
assert served["trace_id"] == chat_span["trace_id"] == root["trace_id"] and served["parent_span_id"] == chat_span["span_id"]
assert served["kind"] == "SERVER" and chat_span["kind"] == "CLIENT"
assert orphan["trace_id"] != root["trace_id"] and orphan["parent_span_id"] is None  # without the header: a new trace
around_ms = chat_span["duration_ms"] - served["duration_ms"]  # connection, HTTP and the handler around the span
assert served["duration_ms"] >= 20 and around_ms > 0
print(round(served["duration_ms"], 1), round(around_ms, 1))
```

В потоке обработчика `CURRENT.get()` возвращает `None`: новый поток не наследует контекст вызывающего, и связь между спанами даёт только заголовок. С заголовком спан сервиса получил `trace_id` клиента, а родителем — спан `chat`. Без заголовка трассировщик начал новую трассу, и спан сервиса стал корнем. Время вокруг работы сервиса — соединение, разбор HTTP и обработчик — у автора составило несколько миллисекунд. В авторском прогоне трасс разрыв между спаном `chat` и временем llama-server в медиане был 8 мс.

Критическая ошибка — склеивать трассы двух сервисов по времени или по совпадению текста запроса. При параллельных запросах такое соединение ошибается, а `trace_id` из заголовка — нет. Вторая ошибка — писать спан сервиса с родителем из локального контекста потока: там его нет, и получится отдельная трасса.

## M13-L07X-B-C

**B.** Доля `chat` — 5970 / 6000 ≈ 0.995. Сервер работал 2400 + 1500 = 3900 мс, а клиент ждал на 5970 − 3900 = 2070 мс дольше. В авторском прогоне медиана этого разрыва — 8 мс, поэтому 2 с — не сеть и не разбор JSON. Ищут очередь на сервере: слот был занят другим запросом. Так выглядела трасса после брошенного запроса: разрыв 1640 мс. Подтверждение — лог llama-server: время `launch_slot` и `release` соседней задачи. Без атрибутов сервера в спане эти 2 с выглядели бы как медленная модель.

**C.** Корень — `invoke_workflow interview-turn` (INTERNAL) с id хода; id сессии идёт в `gen_ai.conversation.id`. Дочерние спаны:
- `transcribe` (INTERNAL, Vosk в процессе) — длительность аудио, модель, число слов;
- `retrieval` — `top_k` и id фрагментов;
- `chat {model}` (CLIENT) — модель, токены, prefill и decode;
- `synthesize` (INTERNAL, SAPI или Piper) — число символов и длительность звука.

HTTP-обработчик веб-сервера — спан SERVER, браузер передаёт ему `traceparent`. Аудио, распознанный текст, ответ кандидата и отзыв модели — персональные данные: по умолчанию их не пишут, остаются длительности, размеры, число токенов и id. Перебивание (barge-in) — не ошибка: ход помечают атрибутом вроде `course.turn.cancelled`, а статус ERROR оставляют для сбоев. Оценку ответа ставят позже, вручную или проверкой. Её записывают событием `gen_ai.evaluation.result` с `gen_ai.response.id`, и событие находит свою трассу, даже если пришло через день.
