## M13-L01

**Условие:** Составь манифест для тренажёра, у которого обновился только поисковый корпус. Укажи минимум восемь полей и объясни, какие файлы нужно сохранить для воспроизведения. Затем сравни два JSON с разным порядком ключей и докажи одинаковую каноническую сумму.

**Обоснованное решение:** Нужны release_id, code_commit, model_id и hash весов, tokenizer_id, prompt_hash, corpus_hash, index_hash, retrieval_config, evaluation_version, dependency_lock, created_at. Для восстановления нужны сами документы, индекс или воспроизводимый рецепт его создания, код, конфигурация и доступные локальные веса. Хеш без файла недостаточен. `json.dumps(obj, sort_keys=True, separators=(',', ':'))` обеспечивает одинаковое представление для перестановок ключей одного объекта; оно не превращает два разных типа, например 2 и"2", в одинаковый объект.

**Что проверить в своей работе:** результат должен следовать из приведённых входов и принятого контракта. Если использованы другие числа или данные, пересчитай вывод; совпадение формулировки с эталоном не требуется. Критическая ошибка — объявить проверенным то, что не было выполнено. После чтения реши новый вариант из урока и отметь объём помощи.

## M13-L03

**Условие:** Для функции оценки интервью подготовь три вида тестов: структуру JSON, проверку конкретного факта и проверку рубрики. Придумай дефект, который проходит первый тест, но проваливает второй; затем дефект, который проходит первые два, но проваливает третий.

**Обоснованное решение:** Структура: обязательные поля score, evidence, next_step нужных типов. Факт: ответ о транзакции должен различать commit и rollback. Рубрика: оценка должна ссылаться на фактически сказанное кандидатом и предлагать исправление конкретного пробела. Дефект 1: JSON корректен, но commit описан как отмена. Дефект 2: объяснение транзакции верно, однако кандидату приписано знание, которого в его ответе нет. Это показывает, почему корректность общего технического текста не заменяет проверку справедливости персональной обратной связи.

## M13-L04

**Условие:** Для двадцати запросов сохрани total_ms, queue_ms, asr_ms и generation_ms. В учебной таблице пусть у четырёх запросов очередь составляет 900 мс, у остальных 0; ASR200 мс и generation300 мс всегда. Вычисли среднее и p95 общего времени. Предложи проверку причины, которая не сводится к немедленной смене модели.

**Обоснованное решение:** Шестнадцать запросов занимают 500 мс, четыре 1400 мс. Среднее=(16·500+4·1400)/20=680 мс. Nearest-rank p95 — девятнадцатый элемент,1400 мс. Модельная часть постоянна, поэтому сначала проверить конкурентность, длину очереди и политику допуска. Повторить опыт с одним и двумя активными запросами при одинаковых данных, отдельно измеряя ожидание и вычисление. Нельзя утверждать причину только по агрегату; требуется связанный лог или трасса.

## M13-L05

**Обоснованное решение:** Остановить приём новых тяжёлых запросов; зафиксировать состояние и причину; выбрать манифест A; восстановить соответствующий индекс schema1 из сохранённого снимка; загрузить полный комплект; выполнить canary через API; возобновить приём. Текущие запросы либо завершаются на закреплённой версии, либо явно отменяются с возможностью повторить, без смешивания компонентов. Успех: ответ содержит releaseA и контрольный запрос возвращает ожидаемый документ/результат. Дополнительно проверить сохранность сессий. Если снимка нет, нельзя обещать быстрый откат; требуется восстановление индекса из исходных документов.

## M13-HW01

Рабочий эталон реализован в labs/M13/demo.py. Версия 1.0 задаёт y=2x+1, ошибочная 1.1 — y=20x+1. Canary(0→1,2→5,−2→−3) обнаруживает дефект на двух точках. После возврата полного stable объект active.version равен 1.0, а canary проходит. Невалидные True, NaN, строка и неверное поле отклоняются. Сто измеренных вызовов сохраняются в JSONL; конкретные времена зависят от устройства и не являются SLA. Канонический JSON и SHA-256 позволяют связать данные с манифестом. Для настоящего веб-сервиса тот же canary выполняется через API, а нагрузочный опыт отдельно задаёт конкурентность и данные.
