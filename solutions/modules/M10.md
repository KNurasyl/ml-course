# M10: решения для самопроверки

Открывай после собственной попытки. Если ты изучил ключ до решения, новая задача из раздела повторения обязательна для проверки самостоятельности. Числа в учебных примерах не являются оценкой реальных кандидатов.

## M10-L01-A

Пример: {id:"index-v1-01",document_id:"index",version:1,source:"course-authored",text:"Индекс ускоряет чтение, но замедляет некоторые записи"}; v2 содержит уточнение о запросе и селективности. Пересборка создаёт новый snapshot сv2, пересчитывает embedding, проверяет контрольные запросы и переключает active_version. v1 сохраняется в архиве для воспроизведения, но исключается из актуального поиска. Вопрос «Почему индекс не ускорил выборку почти всей таблицы?» требует оговоркиv2; одна общая фразаv1 недостаточна. Корректный ответ не должен обещать ускорение любого чтения.

## M10-L02-A

Recall:0,5;1;0, среднее0,5. Precision:0,5;0,5;0, среднее1/3≈0,333. Первый запрос нашёл один из двух нужных источников, второй нашёл единственный нужный, третий не нашёл ни одного. Близкая тема означает общие признаки текста; подтверждение требует, чтобы конкретный фрагмент поддерживал конкретное утверждение. Высокийcosine не доказывает это отношение.

## M10-L03-A

X=1/6+1/7≈0,30952; Z=1/8+1/6≈0,29167; Y=1/7≈0,14286; W=1/8=0,125. Порядок [X,Z,Y,W]. W не попал в top-2, поэтому перестановка [X,Z] его не добавит. Нужно улучшить первую стадию либо увеличить N. MRR=(1+1/3+0)/3=4/9≈0,4444. Эта величина не описывает нахождение всех релевантных оснований.

## M10-L04-A

a и c — supported. b — insufficient: источник не даёт основания для универсального ускорения; для строгого contradicted нужен контрпример или явное отрицание. d — insufficient: стоимость записи не обсуждается. Ответ: «S1 говорит о расходе места и возможном ускорении некоторых запросов. Этого недостаточно для рекомендации любой таблице. Следующий шаг — измерить конкретные запросы и план исполнения». Последнее предложение является предлагаемой проверкой, а не цитатой из S1.

## M10-L05-A

1. Добавить проверенный источник и snapshot; тест проверяет наличие и содержание. 2. Исследовать анализатор/encoder и candidate Recall; тест проверяет нужный ID в top-10 на фиксированных запросах. 3. Улучшить инструкцию или генератор при неизменном правильном контексте; тест проверяет сохранение оговорок на новых примерах. 4. Включить corpus/model revision в ключ либо инвалидировать старый кэш; тест после обновления не получает старый release_id. Oracle полезен во втором и третьем случаях, чтобы отделить доставку от использования информации.

## M10-HW01

labs/M10/demo.py реализует корпус с ID, TF-IDF, плотный LSA, настоящий MiniLM encoder, RRF, прозрачную эвристику rerank и реальную генерацию SmolLM. Extractive baseline сохраняется отдельно. Новые заметки получают происхождение, версию и релевантные ID. Метрики вычисляются по пересечениям множеств, MRR — по первому релевантному рангу. Для вопроса без ответа обычный recall с нулевым знаменателем не определяется: проверяй корректный отказ отдельно.

Таблица проверки ответа: claim → source → supported/contradicted/insufficient. Если LLM не использовала хороший контекст, это ограничение генератора, а не доказательство плохого поиска. Если документа нет, замена генератора не исправляет отсутствие основания. Смена encoder требует переиндексации; смена корпуса требует нового snapshot и контроля кэша. Английский MiniLM выбран для проверяемого малого эксперимента; качество русского поиска требует отдельной модели и измерений.
