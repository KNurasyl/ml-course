Открывай после собственной попытки. Если ты изучил ключ до решения, новая задача из раздела повторения обязательна для проверки самостоятельности. Числа в учебных примерах не являются оценкой реальных кандидатов.

## M10-L01-A

Пример: {id:"index-v1-01",document_id:"index",version:1,source:"course-authored",text:"Индекс ускоряет чтение, но замедляет некоторые записи"}; v2 содержит уточнение о запросе и селективности. Пересборка создаёт новый snapshot с v2, пересчитывает embedding, проверяет контрольные запросы и переключает active_version. v1 сохраняется в архиве для воспроизведения, но исключается из актуального поиска. Вопрос «Почему индекс не ускорил выборку почти всей таблицы?» требует оговорки v2; одна общая фраза v1 недостаточна. Корректный ответ не должен обещать ускорение любого чтения.

## M10-L02-A

Recall:0,5;1;0, среднее 0,5. Precision:0,5;0,5;0, среднее 1/3≈0,333. Первый запрос нашёл один из двух нужных источников, второй нашёл единственный нужный, третий не нашёл ни одного. Близкая тема означает общие признаки текста; подтверждение требует, чтобы конкретный фрагмент поддерживал конкретное утверждение. Высокий cosine не доказывает это отношение.

X=1/6+1/7≈0,30952; Z=1/8+1/6≈0,29167; Y=1/7≈0,14286; W=1/8=0,125. Порядок [X,Z,Y,W]. W не попал в top-2, поэтому перестановка [X,Z] его не добавит. Нужно улучшить первую стадию либо увеличить N. MRR=(1+1/3+0)/3=4/9≈0,4444. Эта величина не описывает нахождение всех релевантных оснований.

## M10-L04-A

a и c — supported. b — insufficient: источник не даёт основания для универсального ускорения; для строгого contradicted нужен контрпример или явное отрицание. d — insufficient: стоимость записи не обсуждается. Ответ: «S1 говорит о расходе места и возможном ускорении некоторых запросов. Этого недостаточно для рекомендации любой таблице. Следующий шаг — измерить конкретные запросы и план исполнения». Последнее предложение является предлагаемой проверкой, а не цитатой из S1.

## M10-L05-A

1. Добавить проверенный источник и snapshot; тест проверяет наличие и содержание. 2. Исследовать анализатор/encoder и candidate Recall; тест проверяет нужный ID в top-10 на фиксированных запросах. 3. Улучшить инструкцию или генератор при неизменном правильном контексте; тест проверяет сохранение оговорок на новых примерах. 4. Включить corpus/model revision в ключ либо инвалидировать старый кэш; тест после обновления не получает старый release_id. Oracle полезен во втором и третьем случаях, чтобы отделить доставку от использования информации.

## M10-HW01

Полный русский исполняемый ключ — [hw_reference.py](../exercises/M10/hw_reference.py). Он расширяет диагностический корпус двумя темами «пул соединений» и «обратное давление»: четыре собственные версионированные заметки, из которых две текущие и две намеренно ошибочные архивные. Шесть новых gold-вопросов заданы в коде до опыта: два точных, два перефразированных, один с двумя источниками и один без ответа.

```powershell
.\.venv\Scripts\python.exe solutions\exercises\M10\hw_reference.py
```

Нужны уже установленные зависимости курса, локальный MiniLM и Qwen из тренажёра. Команда работает на CPU, сохраняет artifacts/M10/hw-ru/{corpus,gold,policy,report,outputs}.json. Для отдельной проверки поиска есть --retrieval-only; этот режим не завершает всю HW. LSA обучается на этом корпусе, MiniLM использует pretrained веса: это разные методы. Английский MiniLM измеряется на русском с явной границей применимости.

Ключ сравнивает окна по 18 слов и абзацы, в каждой нарезке TF-IDF, LSA, MiniLM и RRF. Document Recall@3 вычисляется после схлопывания chunk IDs по document_id; достаточность реального top3 chunks проверяется отдельно по опорным фразам и затем по смыслу. На пяти answerable вопросах фактический Recall@3: lexical 1.0 в обеих нарезках; LSA 1.0/0.9 (слова/абзацы); MiniLM 0.6/0.8; RRF 1.0/0.9. Это маленький синтетический набор, а не доказательство общего превосходства lexical. У unanswerable recall=N/A. Заданный заранее порог 0.12 не распознал единственный unanswerable — корректных отказов правила 0/1.

В report сохранены полные выдачи и время построения/поиска. Этапы timing включают разную подготовку: load+encode для MiniLM нельзя сравнивать с одним умножением TF-IDF как чистую serving latency. Версия 1 исключается до индексации. Отдельный контролируемый опыт показывает, что cache key с release-v2 не читает старое значение release-v1; это небольшой тест логики кэша, не измерение внешнего сервиса.

Для генерации заранее выбраны paragraph/lexical/top3 и четыре case_id. Все четыре ответа получены настоящей Qwen; raw outputs не исправлены. [Ручной разбор](../../quality/rag-hw/manual-review.json) связывает конкретные утверждения с точным текстом источника. Поле source_by_reviewer означает найденное проверяющим основание, а не ссылку, которую дала модель: модель не указала ID ни в одном из четырёх ответов.

| Случай | Наблюдение в реальном выводе | Решение по рубрике |
|---|---|---|
| hw-term-pool | Ожидание/отказ по дедлайну сохранены, соединения обобщены до всех запросов | Один факт поддержан pool-v2-c1; обобщение недостаточно обосновано; ссылки нет |
| hw-paraphrase-pool | «Да» на вопрос об обязательном ускорении, затем «может» и общие оговорки | Гарантия отвергнута неясно; добавлены ресурсы без основания; ссылки нет |
| hw-two-sources | Два механизма пересказаны, но привязка первого/второго этапа перепутана | Не объяснено, что именно измеряется отдельно; ссылки нет |
| hw-no-answer | Выдуман бюджет «около 500 миллионов тенге» | Ни один источник не подтверждает сумму; критическая ошибка |

Итого 0/4 проходят все требования. Это законченный разбор неудачного опыта, не скрытый успешный пример. В report также есть явно помеченные искусственные отказы retrieval/generation для проверки диагностики; их нельзя смешивать с четырьмя реальными outputs. Для следующего улучшения нужны отдельные dev-случаи отказа и формата/оснований, замороженная конфигурация и новые check-запросы. Этот набор уже просмотрен: обещать по нему независимое качество после настройки нельзя.

## M10-L06: диагностический корпус и полный разбор

[diagnostic_ru.py](../../labs/M10/diagnostic_ru.py) содержит все документы, запросы, chunking и расчёты. Команда `.\.venv\Scripts\python.exe labs\M10\diagnostic_ru.py` сохраняет corpus и report в artifacts/M10/ru. Старые версии исключаются до индексации, но отдельно остаются в version_fault для проверки.

На check лексический Recall@3 документа=1 в обеих нарезках, но support-фраза найдена в top3 chunks лишь 4 раза для окон против 6 для абзацев. Значит, замена генератора не является первым объяснением: контекст потерял часть условия. Английский MiniLM даёт Recall@3=.5 для абзацев, RRF=.667 — объединение ухудшило этот малый набор относительно lexical. Это не доказательство бесполезности semantic retrieval вообще; нужен подходящий язык и новый набор.

Для вопроса с двумя источниками MRR учитывает только первый релевантный документ, поэтому его недостаточно для полноты. Для вопросов без ответа correct_abstention считается отдельно. Порог отказа 0.12 задан до check; все выводы о его качестве ограничены двумя искусственными случаями.

B: удаление отрицания не меняет document_id и document Recall, но меняет достаточность конкретного контекста. C: тест обновления должен проверить active corpus version, индекс, cache key и фактический фрагмент. Наличие актуального файла на диске не гарантирует, что сервис использует его.

## M10-L04-B-C

B: (1) contradicted: конкретный опыт 130>100 — контрпример универсальному ускорению. (2) supported: (130−100)/100=0.30, то есть 30% относительно исходных 100 мс. (3) insufficient: один случай замедления не доказывает отсутствие ускорений во всех остальных условиях. Число 30/130≈23.1% отвечает другому сравнению и здесь неверно.

Корректный ограниченный ответ: «S3 описывает атомарное хранение ключа и результата в локальной базе. Чтобы оценить повтор внешнего платежа и восстановление, нужны протокол обращения к провайдеру и правила сверки результата». Отсутствие поддержки не равно доказательству неизбежного двойного списания; ссылочная валидность не равна entailment.


## M10-L05-B-C

B: cosine(E2(q),E1(d1))=0, cosine(E2(q),E1(d2))=1; система ошибочно поставит d2 первым, хотя формы совпали. ## M10-L03-BM25

При b = 0 знаменатель равен tf + k1 = 2.5, поэтому каждое найденное слово даёт ровно IDF: d1 = 0.470 (только «индекс»), d2 = 0.470 + 0.981 = 1.451, d3 = 0.
