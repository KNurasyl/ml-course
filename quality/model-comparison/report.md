# 0.5B против 4B в тренажёре собеседований

Отчёт задачи T51 плана улучшений 1.2.0. Сравниваются два профиля модели тренажёра (T50) на его собственных задачах:
- `tiny` — Qwen2.5-0.5B-Instruct в float32 через transformers;
- `strong` — Qwen3.5-4B Q4_K_M через llama-server b11803, рассуждения выключены.

Модель на 8 млрд параметров не измерялась: её загрузка (около 5 ГБ) требует отдельного решения автора, и профиль `ru-8b` выключен. Все замеры — 09.11.2026, CPU, 4 потока на модель, жадное декодирование.

Данные лежат в этой папке:
- `collect-tiny.json` и `collect-strong.json` — сырые замеры, включая выводы моделей;
- `annotations.jsonl` — разметка показанной обратной связи.

Пересчёт таблиц без моделей:

```powershell
.\.venv\Scripts\python.exe -m projects.interview_trainer.compare_profiles report
.\.venv\Scripts\python.exe -m pytest -q tests\test_compare_profiles.py
```

Повтор замеров: нужны оба профиля, модели речи T45 и около 25 минут CPU.

```powershell
.\.venv\Scripts\python.exe -m projects.interview_trainer.compare_profiles collect tiny
.\.venv\Scripts\python.exe -m projects.interview_trainer.compare_profiles collect strong
```

## Методика

- **Рубрика.** Берутся 16 случаев M11 (`labs/M11/cases-v2.jsonl` и `cases-v3.jsonl`, по 8 HR и backend) в рабочей конфигурации тренажёра: модель выбирает из вариантов фрагмент, критерий и следующий шаг. Показанная обратная связь размечена по рубрике M11 `feedback-grounding-usefulness-v2`: grounded и useful по шкале 0–2 и критическая ошибка. Правило «прошёл рубрику» записано до сбора: grounded ≥ 1, useful ≥ 1 и нет критической ошибки. Калибровка взята из прежней разметки `quality/evaluation/v3`. Одинаковые показанные тексты получают одинаковые оценки независимо от модели: 8 текстов 0.5B дословно совпали с v3, их оценки перенесены. Разметку сделал автор курса с помощью ИИ. Это не независимая человеческая разметка, и в поле `rater` это записано.
- **Судья.** Каждая модель оценивает 32 показанных ответа из `quality/evaluation/v2` и `v3`, размеченных до этой задачи (18 из 32 прошли). Вердикт — один из шести вариантов: useful 0–2 и есть ли критическая ошибка. Поэтому он всегда разбирается. Тексты для судьи экранированы как данные (T53). Вердикт засчитан, если useful ≥ 1 и нет критической ошибки. Разметку сводим к тому же виду, потому что судья не оценивает grounded. Меры: точность, каппа Коэна, ложные одобрения и отклонения, найденные критические ошибки.
- **JSON.** Те же 16 случаев запрашивают один и тот же объект тремя способами:
  - свободный текст с инструкцией вернуть JSON;
  - JSON-режим: у `tiny` это только правило остановки на законченном объекте, у `strong` — JSON-грамматика llama.cpp;
  - выбор из вариантов: у `tiny` префиксное дерево разрешённых токенов, у `strong` GBNF-грамматика.

  Считаются разобранный JSON и соответствие схеме `validate_observations`.
- **Скорость.** Одна фиксированная подсказка. Для `strong` берутся тайминги llama.cpp. Для `tiny` — две жадные генерации на 1 и на 97 токенов: заполнение промпта — это время первой, декодирование — разность.
- **Голос.** Ответы 16 случаев озвучены SAPI: это синтетический заменитель кандидата. Цепочка: распознавание → обратная связь модели → первый звук ответа, то есть весь WAV у SAPI и первое предложение у Piper. Две речевые конфигурации: Vosk + SAPI (по умолчанию) и faster-whisper + Piper (T45). Распознаватели и голос прогреты до замера.
- **Стоимость.**
  - CPU-секунды процесса Python и llama-server на диалог из четырёх ходов (HR и backend) с речью внутри процесса (Vosk + Piper). Время PowerShell для SAPI сюда не входит.
  - Пиковый рабочий набор процессов, после фазы модели и в конце. В рабочий набор llama-server входят отображённые в память страницы файла модели.

## Результаты

**Рубрика.** 16 ответов на профиль:

| Показатель | 0.5B | 4B |
| --- | --- | --- |
| Прошли рубрику | 8 из 16 | 10 из 16 |
| HR / backend | 2 / 6 | 4 / 6 |
| Средний grounded | 1.50 | 1.69 |
| Критических ошибок | 0 | 0 |
| Порог M11, useful ≥ 1 не ниже 75% | не пройден (50%) | не пройден (62.5%) |

Ни один профиль не проходит порог допуска M11. Критических ошибок нет у обоих, и это заслуга ограниченного вывода, а не моделей: на страницу попадают только точная цитата кандидата и постоянный текст рубрики. 0.5B во всех 16 случаях выбрала первый фрагмент, 4B выбирает фрагмент по содержанию.

**Судья.** 32 ранее размеченных ответа:

| Показатель | 0.5B | 4B |
| --- | --- | --- |
| Точность | 0.41 | 0.56 |
| Каппа Коэна | −0.20 | 0.18 |
| Ложных одобрений / отклонений | 9 / 10 | 2 / 12 |
| Найдено критических из 6 | 1 | 0 |
| Точное совпадение useful | 2 из 32 | 13 из 32 |

Судья 0.5B хуже случайного. Судья 4B строг: одобрил 8 ответов при 18 одобренных разметкой. Он редко пропускает плохое, но не нашёл ни одной из шести критических ошибок. Ни одного из судей нельзя ставить вместо разметки. Для 4B допустимая роль — предварительный отбор на ручной разбор, как и предлагает M11-L04.

**JSON.** 16 случаев, разобрано / по схеме:

| Способ | 0.5B | 4B |
| --- | --- | --- |
| Свободный текст | 9 / 0 | 16 / 16 |
| JSON-режим | 9 / 0 | 16 / 16 |
| Выбор из вариантов | 16 / 16 | 16 / 16 |

Маленькой модели ограничение необходимо: без него ни один объект не прошёл схему. 4B выдаёт правильный объект и по инструкции. Грамматика для неё — страховка, а не условие работы.

**Скорость и стоимость:**

| Показатель | 0.5B | 4B |
| --- | --- | --- |
| Заполнение промпта, токенов/с | 329 | 53 |
| Декодирование, токенов/с | 10.6 | 8.4 |
| Реплика обратной связи, медиана | 2.9 с | 5.8 с |
| Речь → первый звук, Vosk + SAPI, p50 / p95 | 4.9 / 6.2 с | 7.8 / 9.2 с |
| Речь → первый звук, Whisper + Piper, p50 / p95 | 5.9 / 7.0 с | 8.0 / 9.4 с |
| CPU-секунды на диалог из 4 ходов, HR / backend | 69.7 / 85.7 | 101.9 / 140.5 |
| Пиковая память | Python 3.3 ГБ | llama-server 4.4 ГБ и Python 0.2 ГБ |

Больше всего времени в голосовом ходе занимает модель: у 4B около 5.8 из 7.8 секунд. Декодирование у 4B в Q4 почти такое же, как у 0.5B в float32, а заполнение промпта в шесть раз медленнее. Промпт обратной связи — 220–420 токенов, ответ — 18, поэтому скорость определяет заполнение. Piper даёт первый звук за 0.2 с против 0.5 с у SAPI, но Whisper распознаёт дольше Vosk, и в сумме конфигурации близки.

**Находка по памяти.** В первом прогоне 4B пиковый рабочий набор llama-server достиг 9.0 ГБ. Причина — кэш промптов в оперативной памяти, по умолчанию до 8 ГиБ (`--cache-ram 8192`): каждый новый промпт добавлял около 100 МБ. Тренажёр отправляет `cache_prompt: false`, так что кэш только занимал память. Профиль `strong` теперь запускает сервер с `--cache-ram 0`. Повторный прогон дал 4.4 ГБ, выводы модели совпали дословно, а голосовая задержка стала ниже (p50 7.8 с против 8.6 с).

## Таксономия ошибок 4B

Шесть ответов 4B не прошли рубрику. Коды выросли из чтения ответов (открытое кодирование, M11-L07X), один ответ может нести несколько кодов:

| Код | Ответов | Что происходит |
| --- | --- | --- |
| `asks_for_given` | 4 | Следующий шаг просит то, что кандидат уже сказал: «Уточни, что именно сделал ты» после описанного действия |
| `misses_key_gap` | 2 | Главный пробел не затронут: неизмеренный результат, оговорка о меняющейся нагрузке |
| `irrelevant_source` | 2 | Найденные источники не покрывают утверждение, проверить по ним нельзя |

Ещё четыре кода описывают более мягкие недочёты. В скобках — число ответов 4B с этим кодом, включая не прошедшие:
- `criterion_mismatch` (3) — критерий не подходит к цитате;
- `partly_repeats` (3) — следующий шаг частично повторяет сказанное;
- `wrong_claim_only_verify` (2) — неверное утверждение только отправлено на проверку, явного разбора нет;
- `generic_verify` (2) — общий шаг «проверь по источнику».

Главный вывод: ошибки 4B определяет устройство продукта, а не размер модели.
- На каждый трек есть только три постоянных следующих шага. Если кандидат уже ответил на всё, что они спрашивают, правильного варианта в списке просто нет.
- Справочный корпус тренажёра — пять документов, поэтому для таймаутов и распределения задержек источника не находится.

Следующие гипотезы, которые стоит проверить: следующие шаги из `expected_properties` и критериев базы вопросов (T52), вариант «ответ полон, переходим дальше» и корпус шире пяти документов.

## Ограничения

- 16 случаев и 32 ответа для судьи — малые авторские наборы. Разница 8 и 10 из 16 не даёт статистически надёжного вывода.
- Разметка рубрики — авторская с помощью ИИ, а не независимая человеческая. Согласие судьи измерено с этой же разметкой.
- Голос ученика заменён синтезом SAPI. Задержки на живой речи и с шумом будут другими.
- Замер одной машины. CPU-секунды и память зависят от процессора и ОС, а рабочий набор llama-server включает отображённые страницы файла модели.
- Модель на 8 млрд параметров не измерялась.
