Версия 1.1.0. Реализуй retrieval_scores(ranking,relevant,k,abstained) в копии starter.py. ranking — уникальные ID документов по убыванию score. relevant — ID правильных документов. k — положительный int, bool не допускается. Повтор ID в ranking является ошибкой входного контракта: схлопни chunks до вызова.

Для answerable верни recall по первым k, MRR по первому правильному документу во всём ранге и correct_abstention=None. Для relevant=[] верни recall=None,mrr=None и фактическую правильность отказа. Не включай None в средний recall.

```powershell

```

## Дополнительные упражнения (версия 1.2.0)

Ещё два контракта по урокам M10-L01, M10-L02, M10-L03, M10-L04 и M10-L06. Скопируй стартер в `submissions/M10/` под тем же именем, реализуй функции и проверь:

```powershell
.\.venv\Scripts\python.exe exercises\M10\check_ex02.py submissions\M10\ex02_fusion.py
.\.venv\Scripts\python.exe exercises\M10\check_ex03.py submissions\M10\ex03_context.py
```

| Упражнение | Уроки | Что реализовать |
| --- | --- | --- |
| `ex02_fusion.py` | M10-L02, M10-L03, M10-L06 | RRF с рангами от 1 и ничьей по ID; candidate Recall@N пула для reranker; MRR только по вопросам, у которых есть ответ |
| `ex03_context.py` | M10-L01, M10-L04, M10-L06 | Окна по словам с overlap; отбор целых chunks в бюджет токенов без устаревших версий и дубликатов |

Как устроена проверка. Числа сравниваются с допуском. Случайные выдачи сверяются с точным расчётом RRF на дробях `Fraction`, который проверка делает сама; окна — с формулой числа окон. Свойства: score RRF лежит в (0, m/(c + 1)], новый список не уменьшает ни один score, а одиночный список сохраняет свой порядок; candidate recall не убывает с ростом N; релевантный документ на первом месте даёт MRR = 1; соседние окна перекрываются ровно на overlap слов и покрывают весь документ; выбранные chunks идут в порядке выдачи, укладываются в бюджет, а каждая причина исключения — obsolete, duplicate или budget — соответствует правилу. Вопрос без ответа не превращается в ноль: recall и MRR там не определены. Отдельный случай — точная ничья, где одинаковые суммы дробей во float расходятся в последнем знаке: порядок по ID должен сохраниться. `--seed 7` даёт новый набор случайных входов. Часть случаев скрыта в `tests/hidden/` — по правилам самопроверки их не открывают.

Зелёная проверка подтверждает поведение функций, но не понимание: после неё объясни в журнале, почему reranker не исправит документ вне top-N и почему обрезанный по бюджету chunk опаснее пропущенного целиком. Эталоны — [ex02](../../solutions/exercises/M10/ex02_fusion.py), [ex03](../../solutions/exercises/M10/ex03_context.py); открывай их только после своей попытки.
