# M02: собственная реализация и проверка

Версия 1.1.0. Эти файлы — заготовка задания, а не готовое решение. Скопируй starter.py в submissions/M02/solution.py. Реализуй контракты docstring; исходную заготовку сохраняй неизменной. Пустой starter намеренно не проходит проверку и не является сломанной лабораторной.

Из корня курса:

```powershell
.\.venv\Scripts\python.exe exercises\M02\check.py submissions\M02\solution.py
```

Checker загружает **твой** Python-файл и проверяет его поведение на фиксированных случаях, включая ошибки. Не запускай чужой непроверенный файл. Exit code 0 означает прохождение перечисленных технических проверок; он не оценивает объяснение и самостоятельность. Сохрани JSON и собственное объяснение рядом с работой. При провале посмотри вход из check.py, воспроизведи его вручную и исправь причину.

После собственной попытки можно сравнить с [эталоном](../../solutions/exercises/M02/solution.py). Проверка эталона той же командой с соответствующим путём подтверждает, что контракт выполним. После полного разбора реши вариант B, а через 3–7 дней вариант C из [модуля](../../course/modules/M02.md). Ключи разных вариантов находятся в [решениях модуля](../../solutions/modules/M02.md).

Окружение: существующий Python 3.11, requirements.lock.txt курса, CPU. Платных API и GPU нет. Все маленькие данные авторские. Для перехода дальше обязательны все предметные критерии, отсутствие критических ошибок и самостоятельное объяснение нового случая.

## Дополнительные упражнения (версия 1.2.0)

Ещё два контракта по урокам M02-L03 и M02-L04. Скопируй стартер в `submissions/M02/` под тем же именем, реализуй функции и проверь:

```powershell
.\.venv\Scripts\python.exe exercises\M02\check_ex02.py submissions\M02\ex02_matrices.py
.\.venv\Scripts\python.exe exercises\M02\check_ex03.py submissions\M02\ex03_scaling.py
```

| Упражнение | Урок | Что реализовать |
| --- | --- | --- |
| `ex02_matrices.py` | M02-L03 | `matmul` без NumPy с проверкой форм и `apply_in_order` — применить преобразования в указанном порядке |
| `ex03_scaling.py` | M02-L04 | `fit_scale` (среднее и разброс по столбцам, делим на n), `apply_scale` и `nearest` с правилом равенства |

Как устроена проверка. Числа сравниваются с допуском, а не побайтово. Кроме фиксированных примеров проверка берёт случайные входы и проверяет свойства, которые должны выполняться всегда: например, (XY)Z = X(YZ), а после масштабирования ближайший сосед не зависит от единиц признака. Флаг `--seed 7` даёт новый набор случайных входов: решение должно проходить при любом seed. Часть случаев скрыта в `tests/hidden/` — по правилам самопроверки их не открывают, иначе проверка превращается в подгонку под известные ответы. Сообщение об ошибке называет вход, ожидание и фактический результат.

Зелёная проверка подтверждает поведение функций, но не понимание: после неё объясни в журнале, почему порядок матриц нельзя менять и почему масштаб признака меняет ближайшего соседа. Эталоны — [ex02](../../solutions/exercises/M02/ex02_matrices.py), [ex03](../../solutions/exercises/M02/ex03_scaling.py); открывай их только после своей попытки.
