# M09: терминальный ответ после невалидного JSON

Версия 1.1.0. Реализуй respond(raw). Валидный JSON содержит только feedback (непустая строка) и score (именно int, не bool, от0 до2). Верни status=ok, исходные feedback/score и fallback_used=False.

При любом неверном формате верни status=needs_review, осмысленное сообщение о ручной проверке, score=None, fallback_used=True. Не извлекай похожий JSON из произвольного окружающего текста и не выдумывай оценку. Это конечный fallback, повторов модели здесь нет.

```powershell
.\.venv\Scripts\python.exe exercises\M09\check.py submissions\M09\solution.py
```

До ключа проверь пустой вывод, лишнее поле, bool, оборванную строку и валидную границу2. B: JSON верен, но текст совета не подтверждён ответом кандидата — форматный checker не должен называться проверкой истины. C через неделю: сервер получил тот же невалидный вывод три раза; этот контракт всё равно возвращает один конечный отказ, не входит в бесконечный цикл. Эталон расположен отдельно в solutions/exercises/M09/solution.py.
