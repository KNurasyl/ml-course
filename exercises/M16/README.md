# M16: самостоятельный компонент

Версия 1.1.0. Новая политика: state содержит topic, turn, clarifications, topics; на тему разрешено limit уточнений. Короткий (<80 символов) или «не знаю» вызывает уточнение пока есть бюджет; отказ («не хочу», «пропуст», «отказываюсь») переводит далее сразу. После бюджета тема меняется. Функция чистая, завершённая сессия и недопустимый ответ отклоняются ValueError. Вариант отличается от bool-политики эталона: limit=2 и пять тем.

Скопируй starter.py в submissions/M16/my_solution.py, реализуй функцию и сохрани объяснение решения. Не открывай готовый solution до первой попытки.

```powershell
.\.venv\Scripts\python.exe exercises\M16\check.py submissions\M16\my_solution.py
```

Проверка возвращает behavior_passed; самостоятельность и понимание она не определяет. При ошибке сократи свой пример и объясни нарушенный контракт. Стартовый файл намеренно не проходит проверку.

После попытки: [полное решение](../../solutions/exercises/M16/solution.py). Проверка ключа и чувствительности к намеренному дефекту:

```powershell
.\.venv\Scripts\python.exe exercises\M16\check.py solutions\exercises\M16\solution.py --self-test
```

Новый пример после просмотра решения приведён в соответствующем новом уроке и ключе модуля. Нельзя считать повторный запуск этого же ключа самостоятельным результатом.
