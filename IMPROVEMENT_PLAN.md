Дата составления: 03.11.2026. Основания: локальный аудит 03.11.2026 (оценка 6,6/10) и внешнее исследование `quality/research-2026-11-03.md` (рынок 2026, эталонные программы, прикладной стек, педагогика).

Этот файл — рабочий бэклог для агента (Claude Code) и для автора. Задачи выполняются по фазам, статус отмечается прямо здесь, в разделе 7.

## 0. Как работать с этим файлом

1. Сначала прочитать `AGENTS.md`, затем этот файл, затем нужный раздел `quality/research-2026-11-03.md`.
2. Одна задача = один коммит (или одна ветка `improve/Txx-кратко`). В сообщении коммита указывать ID задачи.
3. Перед первой задачей фазы выполнить T05 (скрипт `tools/check_no_loss.py`) — без него нельзя доказать, что контент не потерян.
4. Для каждой задачи: снимок «до» → изменения → протокол проверки (раздел 2) → отметка в разделе 7 с датой.
5. **Ничего не удалять и не сокращать.** Уроки, задачи A/B/C, решения, лабораторные, ноутбуки, тесты, отрицательные результаты экспериментов остаются. Разрешены только: добавление, переименование заголовков по словарю (раздел 3.3), перенос ссылок в отдельный раздел, добавление метаданных.
6. Если задача требует необратимого решения или данных, которых нет (URL репозитория, выбор лицензии, установка крупной модели > 1 ГБ), остановиться и спросить автора. Решения, которые можно отменить, принимать самостоятельно и записывать в раздел 7.
7. Окружение: Windows, PowerShell, `.venv\Scripts\python.exe`, Python 3.11.9. Зависимости не ставить глобально. Новые зависимости добавлять в `requirements.in` → пересобрать `requirements.lock.txt`; крупные опциональные пакеты (torch-расширения, llama-cpp-python, faster-whisper) выносить в `requirements-optional.in`.
8. После изменения Markdown: `build_reader.py`, затем `build_manifest.py`, затем `validate_course.py --require-local`. После изменения кода: `pytest -q` и затронутые ноутбуки/лабораторные.

- Не удалять P01–P10, разобранные примеры, варианты B/C — экономию даёт маршрутизация (T10), а не удаление.
- Не делать vLLM, SGLang, Docker, Langfuse, облако, платный API, GPU обязательными.
- Не менять модель по умолчанию в тестах на 4B.
- Не «исправлять» отрицательные результаты; новые эксперименты — рядом.
- Не затаскивать агентные фреймворки (LangGraph, Pydantic AI, OpenAI Agents SDK, Claude Agent SDK, smolagents) дальше обзорной таблицы.
- Не мигрировать сборку на MkDocs/Quarto/Docusaurus, если теряется офлайн-функциональность.
- Не превращать автопроверку в подгонку: зачёт = скрытые случаи + новый вариант без подсказок + объяснение в журнале.
- Не вносить в уроки доли навыков из вакансий как факт — только как ориентир с датой.
- Не добавлять аналогию без «где ломается».
- Не запускать генераторы из `.authoring` (архив версии 0.1.0 перезапишет материалы).

### 7.1. T01: команды для автора

Выполнять из корня курса в PowerShell после того, как автор создаст пустой приватный проект в GitLab и сообщит его URL. Агент эти команды не запускает: push публикует историю на внешний сервис.

```powershell
# 1. Удалённый репозиторий (URL от автора, например git@gitlab.com:<namespace>/ml-llm-course.git)
git remote add origin <URL>
git remote -v

# 2. Аннотированный тег на коммите выпуска 1.1.0 (до работ фазы 0)
git tag -a v1.1.0 b312aff -m "ML/LLM self-study course 1.1.0"
git show --no-patch v1.1.0

# 3. Публикация ветки и тега
git push -u origin main
git push origin v1.1.0

# 4. Проверка критерия приёмки
git remote -v
git ls-remote --heads --tags origin
```

Пустой проект можно создать и из терминала: `glab repo create ml-llm-course --private` (затем `glab repo view --web` покажет URL). Тег `v1.1.1` для завершённой фазы 0 (раздел 6, шаг 1) — отдельное решение автора, в эти команды не входит.
