# Сквозной проект: голосовой тренажёр собеседований

Версия задания 0.2.0. Текущий статус: требования и учебный маршрут. Готовый голосовой продукт и проверенная производительность пока не заявлены. Проект развивается после освоения необходимых тем; ранний пилот проверяет основы и первую архитектуру.

## Пользователь и два режима

Пользователь выбирает тренировку HR или backend-интервью, проходит беседу и получает разбор с примерами из своих ответов. Цель продукта — помочь подготовиться. Результат тренировки не является решением о найме или достоверным измерением профессионального грейда.

HR-ветка проверяет ясность, конкретность и аргументацию. Техническая ветка охватывает Python, API, SQL и основы архитектуры backend-систем. Они имеют отдельные сценарии, рубрики и наборы оценивания; оценки не объединяются в одно число без объяснения.

## Развитие по этапам

| Этап | Проверяемый результат |
| --- | --- |
| Сценарии | Два описанных процесса: начало, вопрос, уточнение, переход, завершение и обратная связь |
| Текстовый диалог | Сессия хранит состояние, корректно завершается и выдерживает неполный ответ и отказ зависимости |
| Поиск и RAG | Техническое объяснение опирается на найденные источники; ошибки поиска отделяются от ошибок генерации |
| Оценивание | Рубрики применены к ручной разметке; изменения проверяются на регрессии |
| Голос | Микрофон → ASR → диалог → TTS → воспроизведение; пауза, перебивание и отмена не смешивают ответы разных ходов |
| Эксплуатация | Версии, журнал ошибок, нагрузочные измерения, остановка и откат воспроизводимы |
| Пилот продукта | Согласившиеся участники выполнили реальные сессии; замечания и исправления задокументированы |

Для первого архитектурного рисунка достаточно браузера, API сессий, контроллера диалога, модели и хранилища. Позже появляются индекс знаний, оценивание и голосовой контур. Необходимость каждого дополнительного компонента объясняется конкретной задачей или отказом.

## Проверки качества

Для HR: обратная связь ссылается на реальный фрагмент ответа; не приписывает не сказанный опыт; отделяет наблюдение от рекомендации. Для технического режима: объяснение корректно по заданной задаче, учитывает условия, признаёт недостаток сведений и приводит подходящий источник, когда он нужен.

В обоих режимах проверяются непротиворечивость сценария, корректное завершение, ошибки внешних компонентов и повторяемость оценки. Оценка моделью сравнивается с ручной; высокая согласованность на нескольких учебных примерах ещё не доказывает качество на новых разговорах.

В голосовом контуре измеряются ошибки распознавания на выбранной речи, ошибки смысла после ASR, задержки по этапам, потерянные или смешанные реплики, успешность отмены. Сначала локальный небольшой контур; конкретная модель и численные целевые задержки фиксируются после замеров на ноутбуке.

## Начальные данные в репозитории

`data/interview/hr-development.json`: восемь синтетических случаев для HR-рубрики. `data/interview/backend-development.json`: двенадцать синтетических технических случаев. В каждом есть вопрос, ответ, ожидаемое направление обратной связи и отдельные критерии. Происхождение и статус описаны в `data/interview/README.md`.

Это открытый набор разработки, подготовленный автором курса, без реальной независимой разметки. В M11 ученик готовит процедуру разметки и отдельную проверку, которую не использует для повседневной настройки. До этого нельзя называть начальные данные подтверждённым эталоном качества.

## Итоговая сдача

Нужны воспроизводимый запуск, демонстрационные HR- и техническая сессии, описание данных, сравнение решений, разбор неудачных примеров, измерения на указанном оборудовании, архитектура и инструкция восстановления. Эталонный пример курса хранится отдельно от работы ученика и будет разработан в поздних модулях.

На защите ученик объясняет путь реплики через систему, выбор модели и поиска, границы рубрик, стоимость и задержку вычислений, а затем изменяет заданное условие без готового решения. Портфолио оценивается отдельно от факта прохождения уроков.
