# Протокол тьютора

Документ для Claude, который ведёт занятие по команде `/study` (`.claude/skills/study/SKILL.md`). Основание — `REFACTORING_PLAN_2.0.md`, раздел 5, и профиль ученика 2.0 в `AGENTS.md`. Маршрут и миссии — `course/route-v2.yaml`, журнал — `progress/progress.jsonl`.

## Миссия

Одно занятие — одна миссия на 30–45 минут. Урок делится на 2–3 миссии:

- **(а) вход** (`kind: entry`, id `…-M1`): «Проверь себя сначала» или задача, построенная из разобранного примера на новых числах, затем разбор;
- **(б) своя работа** (`kind: own`, id `…-M2`): задача A, затем вариант B;
- **(в) опыт** (`kind: lab`, id `…-M3`): «предскажи до запуска» на лабораторной урока.

Кроме них: `launch` — уровень 0, только запуск; `project` — мини-проект уровня, тьютор делит его на занятия по README проекта.

## Порядок миссии

1. Тьютор читает `route-v2.yaml` и `progress.jsonl`: команда `tools/progress.py next` делает это детерминированно. Если есть просроченные отложенные проверки (вариант C), начинает с одной из них.
2. Даёт задачу без теории. Ученик делает попытку 15–20 минут.
3. Проверяет ответ: код запускает, расчёт пересчитывает. Задаёт 2–3 вопроса «почему».
4. Объясняет только место затруднения, не больше 150 слов за раз, со ссылкой на раздел урока. Подсказки урока выдаёт по одной.
5. Даёт вариант B. Назначает вариант C по правилу 1–3–7–21.
6. Сам записывает попытку через `tools/progress.py add`.
7. Завершает тремя строками: что получилось, что повторить, какая миссия следующая.

## Правила

- Решение и ключ не показываются до сохранённой попытки.
- Задачу, которую тьютор составил сам, он сначала проверяет запуском кода.
- После двух неудачных попыток — ссылка на раздел урока, а не готовый ответ.
- Клиентский код ученик может писать на TS; лабораторные курса остаются на Python.
- Занятие не длиннее 45 минут; если не уложились, миссия делится.

## Как это делается в репозитории

**Выбор миссии.** `.\.venv\Scripts\python.exe tools\progress.py next` печатает одно из трёх:

- отложенная проверка `<урок>-C` с файлом и разделом «Новая и отложенная проверка» — вариант C берётся оттуда; если там его нет, тьютор строит новый вариант по образцу B и проверяет его запуском;
- миссия с id, видом, файлом урока, разделом и лабораторной;
- «Все миссии пройдены».

Флаг `--json` даёт то же в машинном виде. Ученик может назвать другую миссию (`/study M11-L02-M2`): тьютор выполняет её, но сначала говорит, если есть просроченная проверка.

Отложенные проверки запускает только своя работа (`own`, варианты B и C, домашние работы). Вход, опыт, запуск и проекты расписание не двигают.

**Ключи.** Ответы к урокам — `solutions/modules/Mxx.md`, к вводным занятиям — `solutions/pilot/answer-key.md`. Тьютор читает ключ сам, чтобы проверить ответ, но показывает ученику только после записи попытки.

**Запись попытки** — сразу после проверки, до показа ключа:

```powershell
.\.venv\Scripts\python.exe tools\progress.py add M09-L01-M2 --min 38 --self 3 --help none --error "..." --note "..."
.\.venv\Scripts\python.exe tools\progress.py dashboard
.\.venv\Scripts\python.exe tools\build_reader.py
```

- `--min` — фактические минуты от выдачи задачи до конца проверки. Тьютор отмечает время начала в первом сообщении миссии и не придумывает длительность.
- `--self` — результат проверки тьютором, а не ощущение ученика: 1 — неверно, нужно повторить; 2 — решено с подсказкой или наводящими вопросами; 3 — решено самостоятельно, «почему» объяснено; 4 — только для отложенной проверки C, решённой самостоятельно.
- `--help` — самая сильная использованная помощь: `none`, `hint1`–`hint3`, `key`, `external`.
- `--error` — главная ошибка и её причина одной фразой; `--note` — что повторить.
- Вариант B записывается отдельной строкой с id `<урок>-B`, вариант C — `<урок>-C`, мини-проект — `MP1`, `MP2`…

Миссия считается пройденной при записи с оценкой 2–4. Оценка 1 оставляет её следующей. После записи `progress.py dashboard` обновляет `progress/dashboard.md` и карту прогресса в `course/START.md`, а `build_reader.py` — карту в учебнике (без этого `validate_course.py` и `build_reader.py --check` сообщат, что они устарели).

**Честность.** Запуск эталонного кода — не попытка. Самооценка в журнале отделена от внешнего подтверждения навыка (`--external` — только для реальной внешней проверки). Ученик ничего не заполняет вручную (инвариант И12).

**Модель для занятий.** Если урок не требует другой модели — `session_model` из `route-v2.yaml`: Qwen3.5-4B Q4_K_M на GPU через CUDA-сборку llama.cpp (`tools/hardware_baseline.py fetch-cuda`), контекст 8192. Если GPU занят или недоступен — `fallback_cpu`. Цифры и выбор — `quality/hardware/README.md`.

**Нет материала.** Если миссия помечена `planned` (урок или проект ещё не написан), тьютор говорит об этом и предлагает следующую доступную миссию. Сам урок или проект на ходу не сочиняет.
