## M00. Модель и обучение

### [M00-L01. От входа к предсказанию](lessons/M00-L01.md)

- **Правило.** ŷ = f(x); для линейной модели ŷ = w·x + b. Инференс — применение готового правила к новому входу, правило при этом не меняется.
- **Смысл величин.** x — вход, его смысл и единицы задаёт инженер; ŷ — предсказание; y — известный правильный ответ; w и b — числа, задающие правило.
- **Когда применять.** Всякий раз, когда нужно отделить вычисление ответа от подбора правила. Пример: ŷ = 2x + 1 при x = 3 даёт 7, повторный вызов с другим x правило не меняет.
- **Главная ошибка.** Считать вызов модели обучением или путать предсказание ŷ с правильным ответом y.

### [M00-L02. Параметры и устройство модели](lessons/M00-L02.md)

- **Правило.** Архитектура — вид вычисления (w·x + b), параметры — конкретные числа w и b, состояние приложения — данные вне модели, например история запросов.
- **Смысл величин.** w — наклон: при росте x на 1 ответ меняется на w; b — ответ при x = 0, его изменение сдвигает все ответы одинаково.
- **Когда применять.** При сохранении, загрузке и выпуске модели: релиз = архитектура + параметры + порядок признаков + подготовка входа + версия. Пример: b с 1 на 3 сдвигает все ответы на +2.
- **Главная ошибка.** Сохранять параметры без архитектуры и версии или считать запись истории запросов изменением параметров.

### [M00-L03. Ошибка и подбор параметров](lessons/M00-L03.md)

- **Правило.** MSE = (e₁² + … + eₙ²)/n, где eᵢ = ŷᵢ − yᵢ; кандидатов сравнивают на одних и тех же объектах по одному правилу.
- **Смысл величин.** eᵢ — остаток (плюс — завышение, минус — занижение); квадрат усиливает большие промахи; n — число объектов, при n = 0 ошибка не определена; единицы MSE — квадрат единиц y.
- **Когда применять.** При выборе параметров по таблице с известными ответами. Пример: остатки [1, −1, 2] дают MSE = (1 + 1 + 4)/3 = 2.
- **Главная ошибка.** Усреднять остатки без квадрата, так что ошибки разных знаков гасят друг друга, или выдавать меньшую MSE на обучающей таблице за качество на новых данных.

### [M00-L04. Обучение и применение](lessons/M00-L04.md)

- **Правило.** Обучение меняет обучаемые параметры по данным и цели; инференс применяет модель; контекст — содержимое одного вызова; история и индекс — данные приложения.
- **Смысл величин.** Веса — обучаемые параметры (все или только адаптер); контекст — токены конкретного запроса; RAG-индекс — корпус, из которого ищут фрагменты для контекста.
- **Когда применять.** При разборе вопроса «почему ответ изменился или не изменился»: проследи, какой артефакт поменяло действие — веса, контекст, историю или индекс.
- **Главная ошибка.** Считать, что сохранённая история или новый документ в корпусе меняют веса модели или сами попадают в контекст.

### [M00-L05. Первая схема ML-сервиса](lessons/M00-L05.md)

- **Правило.** Два контура: подготовка модели (данные, обучение, оценка, артефакт) и запрос (контракт, загрузка версии, инференс, ответ); запрос модель не обучает.
- **Смысл величин.** Контракт — тип, допустимые значения и единицы входа; артефакт — параметры, подготовка входа и версия; откат — возврат всего совместимого набора.
- **Когда применять.** При проектировании и выпуске сервиса: каждая стрелка схемы подписана передаваемыми данными, центр и масштаб хранятся и откатываются вместе с весами.
- **Главная ошибка.** Откатывать только веса, оставив подготовку входа от новой версии, или считать быстрый ответ без ошибок доказательством правильных предсказаний.

## M01. Данные и численный Python

### [M01-L01. Массивы и формы](lessons/M01-L01.md)

- **Правило.** Строка — объект, столбец — признак; mean(axis=0) даёт среднее каждого признака; broadcasting сравнивает размеры справа налево, каждая пара должна совпадать или содержать 1.
- **Смысл величин.** shape — число элементов по осям; axis — ось, которая исчезает при сокращении; (3,) — одна ось, (3, 1) — столбец, (1, 3) — строка; dtype — общий тип элементов.
- **Когда применять.** Перед каждой операцией над массивами: выпиши формы входов и ожидаемую форму результата. Пример: (4, 2) − (2,) вычитает вектор из каждой строки и даёт (4, 2).
- **Главная ошибка.** Вычесть (n,) и (n, 1) и получить матрицу n×n вместо n остатков или усреднить по axis=1 признаки в разных единицах.

### [M01-L02. Качество таблицы](lessons/M01-L02.md)

- **Правило.** Сначала определи единицу наблюдения и первичный ключ, затем ищи конфликты ключа, пропуски и нарушения диапазона; каждое правило очистки записывает, что сделано и со сколькими строками.
- **Смысл величин.** Единица наблюдения — что представляет строка; первичный ключ — поля, уникально задающие строку; пропуск — неизвестное значение, а не ноль; доля пропусков = пропуски / строки.
- **Когда применять.** До обучения и при каждом новом источнике данных. Пример: 2 пропуска на 8 строк дают долю 0.25, и причину пропусков нужно выяснить до заполнения.
- **Главная ошибка.** Заменять пропуск нулём или удалять «дубликаты» без проверки, что строки с одним ключом действительно одинаковы.

### [M01-L03. Разделение данных](lessons/M01-L03.md)

- **Правило.** Train — подбор параметров, validation — выбор настроек, test — однократная оценка выбранной процедуры; разбиение повторяет будущий сценарий: по группам, по времени или со стратификацией.
- **Смысл величин.** Группа — связанные строки одного пользователя или сессии, они целиком в одной части; временная граница — прошлое для обучения, будущее для проверки; seed и список ключей делают разбиение воспроизводимым.
- **Когда применять.** До любой подготовки, которая узнаёт свойства данных. Пример: для модели на новых людях обе строки пользователя A попадают в одну часть, а не делятся между train и test.
- **Главная ошибка.** Случайно делить строки одного пользователя между train и test или выбирать лучшую версию по test.

### [M01-L04. SQL и происхождение данных](lessons/M01-L04.md)

- **Правило.** JOIN один-ко-многим повторяет родительскую строку по числу дочерних; признаки уровня сессии получают агрегацией дочерней таблицы до одной строки на ключ, затем проверяют уникальность ключа.
- **Смысл величин.** COUNT(*) — число строк, COUNT(column) — число известных значений; AVG пропускает NULL; LEFT JOIN сохраняет левые строки, но WHERE по правому полю может их удалить.
- **Когда применять.** При сборке признаков из нескольких таблиц. Пример: сессии длятся 20 и 40 с, у первой три ответа — после JOIN среднее (20·3 + 40)/4 = 25 вместо 30.
- **Главная ошибка.** Усреднять поле родителя после JOIN или фильтровать LEFT JOIN условием WHERE по полю правой таблицы.

### [M01-L05. Воспроизводимый конвейер](lessons/M01-L05.md)

- **Правило.** fit вычисляет параметры подготовки только на train и сохраняет их; transform применяет сохранённые параметры к любому входу; центрирование: z = x − μ_train.
- **Смысл величин.** μ_train — среднее обучающей части; артефакт — имена и порядок признаков, статистики и версия; seed — состояние генератора случайных чисел, а не версия данных.
- **Когда применять.** При подготовке признаков для обучения и для сервиса. Пример: train [2, 6], μ = 4; новый x = 9 даёт z = 5, а среднее test после transform не обязано быть нулём.
- **Главная ошибка.** Вызывать fit_transform на test или в сервисе, менять порядок признаков без проверки имён, загружать непроверенный pickle.

## M02. Линейная алгебра

### [M02-L01. Векторы как признаки](lessons/M02-L01.md)

- **Правило.** Вектор — упорядоченный набор чисел; сложение и умножение на число выполняются покоординатно; линейная комбинация αu + βv; разность v − u — изменение по каждой координате.
- **Смысл величин.** Координата — признак в договорённом порядке; α и β — веса комбинации; e₁ и e₂ — базисные направления, x = x₁e₁ + x₂e₂.
- **Когда применять.** Чтобы представить объект признаками или найти изменение между двумя объектами. Пример: u = (4, 1), v = (6, 5) дают v − u = (2, 4) и 0.5u + 0.5v = (5, 3).
- **Главная ошибка.** Переставить координаты или складывать идентификаторы и коды категорий как обычные числа.

### [M02-L02. Скалярное произведение и нормы](lessons/M02-L02.md)

- **Правило.** u·v = Σuᵢvᵢ; ‖u‖ = √Σuᵢ²; cosine = u·v / (‖u‖·‖v‖) для ненулевых векторов, значение от −1 до 1.
- **Смысл величин.** Dot зависит и от длин, и от угла; норма — длина вектора; косинус — сходство направлений; у нулевого вектора направления нет.
- **Когда применять.** Косинус — чтобы сравнить направления, dot — чтобы посчитать вклад признаков в w·x. Пример: u = (1, 2), v = (2, 4) дают cosine = 1, а dot = 10 растёт вместе с длиной v.
- **Главная ошибка.** Делить на нулевую норму без явного правила или считать большой dot большим сходством направлений.

### [M02-L03. Матрицы и композиция](lessons/M02-L03.md)

- **Правило.** (n×d)·(d×k) = n×k: внутренние размеры совпадают; элемент (i, j) — строка i на столбец j; BAx — сначала A, затем B; в общем случае AB ≠ BA.
- **Смысл величин.** n — объекты, d — признаки, k — выходы; транспонирование меняет оси местами; ассоциативность (BA)x = B(Ax) позволяет заранее объединить линейные шаги.
- **Когда применять.** При каждой формуле с матрицами — выписать формы. Пример: X формы (4, 3) и W формы (3, 6) дают XW формы (4, 6).
- **Главная ошибка.** Перемножать по внешним размерам, «чинить» ошибку формы транспонированием наугад или менять порядок преобразований.

### [M02-L04. Сходство и масштаб](lessons/M02-L04.md)

- **Правило.** d(x, z) = √Σ(xᵢ − zᵢ)²; стандартизация zᵢ = (xᵢ − μᵢ)/sᵢ с μ и s по train; нормирование x/‖x‖ работает по строке объекта.
- **Смысл величин.** μᵢ и sᵢ — среднее и разброс признака на train; стандартизация идёт по столбцам, нормирование — по строкам; при sᵢ = 0 делить нельзя.
- **Когда применять.** Перед сравнением объектов по расстоянию, если признаки в разных единицах. Пример: признак в миллисекундах вместо секунд увеличивает свой вклад в квадрат расстояния в миллион раз.
- **Главная ошибка.** Путать стандартизацию столбцов с нормированием строк или вычислять μ и s по всем данным вместе с test.

### [M02-L05. Маленький векторный поиск](lessons/M02-L05.md)

- **Правило.** Точный поиск: нормировать ненулевые векторы, оценки = D̂q̂, взять top-k по убыванию с правилом равенства; recall@k = найденные релевантные / все релевантные.
- **Смысл величин.** q̂ и d̂ — векторы единичной длины, их скалярное произведение равно косинусу; k — размер выдачи; оценка сходства — не вероятность истинности.
- **Когда применять.** Поиск по небольшому корпусу как эталон для проверки приближённых индексов. Пример: релевантны 3 документа, в top-5 найдено 2 — recall@5 = 2/3.
- **Главная ошибка.** Сравнивать векторы разных encoder, оставлять равенства без детерминированного порядка или считать высокий косинус доказательством ответа.

## M03. Производные и оптимизация

### [M03-L01. Изменение функции](lessons/M03-L01.md)

- **Правило.** Производная — предел [f(w + h) − f(w)]/h при h → 0; центральная разность [f(w + h) − f(w − h)]/(2h) обычно точнее при том же h.
- **Смысл величин.** f(w) — высота графика, f′(w) — наклон: его знак показывает направление роста; h — шаг приближения.
- **Когда применять.** Чтобы оценить наклон или проверить формулу производной численно. Пример: f(w) = w² + 3w при w = 1 даёт f′ = 2w + 3 = 5.
- **Главная ошибка.** Путать значение функции с наклоном, брать слишком маленький h или считать нулевой наклон гарантией минимума.

### [M03-L02. Производная и цепное правило](lessons/M03-L02.md)

- **Правило.** Если L = f(g(w)), то dL/dw = f′(g(w))·g′(w); для L = (wx + b − y)²: ∂L/∂w = 2e·x и ∂L/∂b = 2e, где e = ŷ − y.
- **Смысл величин.** e — остаток; 2e — чувствительность потери к предсказанию; x — чувствительность предсказания к весу; частная производная меняет один параметр при фиксированных остальных.
- **Когда применять.** Чтобы вычислить градиент составной функции и проверить его центральной разностью. Пример: x = −1, y = 2, w = 3, b = 0 дают ŷ = −3, e = −5, ∂L/∂w = 10, ∂L/∂b = −10.
- **Главная ошибка.** Забыть множитель x или проверять градиент той же переписанной формулой вместо конечной разности.

### [M03-L03. Градиент на наборе](lessons/M03-L03.md)

- **Правило.** ∂L/∂w = (2/n)Σeᵢxᵢ и ∂L/∂b = (2/n)Σeᵢ; шаг w ← w − η·dw, b ← b − η·db, обе производные считаются по старым параметрам.
- **Смысл величин.** eᵢ — остаток i-го объекта; n — число объектов; η — шаг обучения; в матричной записи dw = (2/n)Xᵀe.
- **Когда применять.** Чтобы обучить линейную модель полным или мини-пакетным градиентом. Пример: x = [1, 2], y = [3, 5], w = b = 0 дают dw = −13 и db = −8.
- **Главная ошибка.** Обновить w и затем считать db по новому w или взять сумму вместо среднего, так что шаг начинает зависеть от размера набора.

### [M03-L04. Шаг обучения](lessons/M03-L04.md)

- **Правило.** Для L = c(w − m)² ошибка параметра δ = w − m меняется как δ_new = (1 − 2cη)δ; спуск сходится при 0 < η < 1/c.
- **Смысл величин.** η — шаг; 1 − 2cη — множитель ошибки за шаг: от 0 до 1 — монотонное приближение, от −1 до 0 — затухающие колебания, по модулю больше 1 — расходимость.
- **Когда применять.** Чтобы выбрать шаг и объяснить медленное обучение, колебания или рост потери. Пример: c = 4 даёт границу η < 0.25; при η = 0.2 множитель равен −0.6.
- **Главная ошибка.** Лечить расходимость большим числом эпох или путать рост validation-ошибки при переобучении с численной расходимостью.

### [M03-L05. Регуляризация и масштаб](lessons/M03-L05.md)

- **Правило.** J = MSE + λw², градиент dJ/dw = dMSE/dw + 2λw; для J = (w − a)² + λw² оптимум w* = a/(1 + λ).
- **Смысл величин.** λ ≥ 0 — сила штрафа; смещение b не штрафуется; штраф тянет вес к нулю, но не делает его точно нулевым.
- **Когда применять.** Чтобы ограничить величину весов; λ выбирают на validation. Пример: a = 9 и λ = 0.5 дают w* = 6.
- **Главная ошибка.** Штрафовать признаки в разных масштабах одним λ без стандартизации или подбирать λ по test.

## M04. Вероятность и статистика

### [M04-L06. Экспонента, логарифм и потеря вероятностного ответа](lessons/M04-L06.md)

- **Правило.** Потеря примера L = −ln(вероятность случившегося исхода): для y = 1 это −ln p, для y = 0 — −ln(1 − p); средняя BCE усредняет потери по примерам.
- **Смысл величин.** p — вероятность класса 1; ln — функция, обратная exp, определена только для положительных чисел; ln(ab) = ln a + ln b превращает произведение вероятностей в сумму.
- **Когда применять.** Чтобы оценить вероятностный классификатор. Пример: y = 1 при p = 0.9 даёт 0.105, а при p = 0.1 — 2.303: уверенная ошибка стоит примерно в 22 раза дороже.
- **Главная ошибка.** Брать −ln p для y = 0 или «чинить» ln(0) нулём вместо проверки области определения.

### [M04-L01. Случайность и условие](lessons/M04-L01.md)

- **Правило.** P(A ∣ B) = P(A∩B)/P(B) при P(B) > 0; полная вероятность P(A) = P(A ∣ B)P(B) + P(A ∣ не B)P(не B); Байес P(B ∣ A) = P(A ∣ B)P(B)/P(A).
- **Смысл величин.** Условие B выбирает строку таблицы, её размер становится знаменателем; P(A ∣ B) и P(B ∣ A) отвечают на разные вопросы; независимость означает P(A ∣ B) = P(A).
- **Когда применять.** Чтобы найти долю внутри подгруппы или пересчитать качество при новом составе. Пример: среди 30 длинных ответов 24 корректны, значит P(корректно ∣ длинный) = 0.8.
- **Главная ошибка.** Путать P(A ∣ B) с P(B ∣ A) или брать для обеих вероятностей один и тот же знаменатель.

### [M04-L02. Среднее, дисперсия и выборка](lessons/M04-L02.md)

- **Правило.** x̄ = (1/n)Σxᵢ; s² = Σ(xᵢ − x̄)²/(n − 1); s = √s²; SE = s/√n.
- **Смысл величин.** s — разброс отдельных наблюдений в исходных единицах; SE — неопределённость оценки среднего; деление на n − 1 используют при оценке по выборке.
- **Когда применять.** Чтобы описать центр и разброс и указать точность среднего. Пример: [1, 4, 10] дают x̄ = 5, s² = 21, s ≈ 4.58, SE ≈ 2.65.
- **Главная ошибка.** Путать s со стандартной ошибкой или «повышать точность» копированием строк.

### [M04-L07. От исходов к распределению и вероятности хвоста](lessons/M04-L07.md)

- **Правило.** P(X = k) = C(n, k)·pᵏ(1 − p)ⁿ⁻ᵏ для n независимых испытаний; P(X ≥ k) — сумма таких вероятностей от k до n.
- **Смысл величин.** X — число успехов; C(n, k) — число последовательностей с k успехами; «не менее k» включает k, «больше k» начинается с k + 1.
- **Когда применять.** Чтобы найти вероятность «не менее k успехов». Пример: n = 6, p = 0.5 дают P(X ≥ 5) = (6 + 1)/64 ≈ 0.109.
- **Главная ошибка.** Забыть граничное значение в «не менее k» или считать последовательности при p ≠ 0.5 равновероятными.

### [M04-L03. Неопределённость метрики](lessons/M04-L03.md)

- **Правило.** p̂ = k/n; SE ≈ √[p̂(1 − p̂)/n]; интервал Уилсона лучше ведёт себя у 0 и 1, чем p̂ ± 1.96·SE.
- **Смысл величин.** k — успехи, n — независимые попытки; интервал описывает неопределённость доли при принятых предположениях, а не диапазон следующей партии.
- **Когда применять.** Чтобы доложить долю успехов с честной неопределённостью. Пример: 45/50 и 450/500 дают одну долю 0.9, но SE ≈ 0.042 и ≈ 0.013.
- **Главная ошибка.** Доложить долю без n или считать, что интервал гарантирует результат следующей партии.

### [M04-L04. Bootstrap и интервалы](lessons/M04-L04.md)

- **Правило.** Парный bootstrap: пересэмплировать индексы пар с возвращением, в каждом наборе считать среднее разностей, интервал — квантили 2.5% и 97.5%.
- **Смысл величин.** Единица пересэмплирования — то, что независимо: вопрос или человек; число повторов влияет на устойчивость квантилей, но не добавляет данных; seed делает расчёт повторимым.
- **Когда применять.** Чтобы оценить неопределённость разницы двух систем на одних примерах. Пример: разности [1, 0, 2] и индексы [0, 0, 2] дают повтор со средним (1 + 1 + 2)/3 ≈ 1.33.
- **Главная ошибка.** Пересэмплировать A и B независимо или считать ответы одного человека независимыми.

### [M04-L05. Гипотезы и эксперимент](lessons/M04-L05.md)

- **Правило.** p-value — вероятность при H₀ получить результат не менее экстремальный; в знаковом тесте при H₀ каждая сторона выигрывает с вероятностью 0.5, ничьи не учитываются.
- **Смысл величин.** α — допустимая частота ложных отклонений; ошибка I рода — отклонить верную H₀, ошибка II рода — пропустить реальный эффект; практическая значимость — величина эффекта и его цена.
- **Когда применять.** Для заранее спланированного парного сравнения. Пример: 9 побед из 10 дают двустороннее p = 22/1024 ≈ 0.021.
- **Главная ошибка.** Читать p-value как вероятность истинности H₀ или проверять много гипотез без поправки.

### [M04-L08. Сколько наблюдений нужно: планирование симуляцией](lessons/M04-L08.md)

- **Правило.** Мощность — вероятность отвергнуть H₀, если верен полезный эффект; объём выбирают из заранее заданной сетки как первый n, где мощность не ниже требуемой.
- **Смысл величин.** p₀ — базовая вероятность, p₁ — минимальный полезный эффект; симуляция с seed оценивает мощность долей отвержений; правило остановки фиксируют до сбора данных.
- **Когда применять.** При планировании сравнения до сбора данных. Пример: 712 отвержений из 1000 симуляций дают мощность ≈ 0.71 — для цели 0.8 нужен больший n.
- **Главная ошибка.** Останавливать сбор при первом хорошем результате или менять сетку и порог после просмотра данных.

## M05. Классический ML

### [M05-L01. Задача и исходное решение](lessons/M05-L01.md)

- **Правило.** Precision = TP/(TP + FP), recall = TP/(TP + FN), accuracy = (TP + TN)/n; модель сравнивают с baseline по той же выборке и тому же положительному классу.
- **Смысл величин.** TP — найденная проблема, FP — ложная тревога, FN — пропуск, TN — верно признанный обычный случай; при нулевом знаменателе метрика не определена.
- **Когда применять.** Чтобы выбрать метрику по цене ошибок. Пример: 40 объектов, 8 положительных, TP = 6, FP = 3, FN = 2 — accuracy 0.875, precision ≈ 0.67, recall 0.75; baseline «всегда 0» даёт accuracy 0.8 при recall 0.
- **Главная ошибка.** Судить по accuracy при редком положительном классе или менять положительный класс между сравниваемыми моделями.

### [M05-L02. Линейные модели](lessons/M05-L02.md)

- **Правило.** z = w·x + b, p = σ(z) = 1/(1 + e^(−z)), класс 1 при p ≥ t; обучение минимизирует BCE = −[y ln p + (1 − y) ln(1 − p)].
- **Смысл величин.** z — линейный score, p — вероятность класса 1 по модели, t — правило решения, а не параметр обучения; C в LogisticRegression — обратная сила штрафа.
- **Когда применять.** Чтобы отделить обучение весов от выбора действия. Пример: z = 1.5 даёт p ≈ 0.818 — при t = 0.5 класс 1, при t = 0.85 класс 0, веса те же.
- **Главная ошибка.** Подбирать порог по test или считать, что смена порога переобучает модель.

### [M05-L03. Деревья и бустинг](lessons/M05-L03.md)

- **Правило.** Прогноз листа регрессии — среднее y его объектов; разбиение уменьшает сумму квадратов ошибок; бустинг F_new = F_old + η·h, где h обучено на остатках y − F_old.
- **Смысл величин.** max_depth и min_samples_leaf ограничивают сложность; η — learning_rate; лес усредняет независимые деревья, бустинг исправляет предыдущие.
- **Когда применять.** Для табличных пороговых зависимостей. Пример: y = [1, 3, 9, 11] при пороге между 3 и 9 дают листья 2 и 10; с F0 = 6 и η = 0.5 дерево остатков даёт F1 = [4, 4, 8, 8].
- **Главная ошибка.** Принимать нулевую train-ошибку глубокого дерева за обобщение или ждать от дерева экстраполяции за диапазон train.

### [M05-L04. Валидация и утечки](lessons/M05-L04.md)

- **Правило.** В k-fold каждый объект ровно один раз попадает в validation; все шаги, зависящие от данных, обучаются на обучающей части fold; test открывают один раз после выбора.
- **Смысл величин.** Splitter: StratifiedKFold — доли классов, GroupKFold — люди, TimeSeriesSplit — время; разброс оценок по folds — чувствительность к разбиению, а не стандартная ошибка.
- **Когда применять.** Чтобы выбрать процедуру без утечки. Пример: train fold [2, 4, 6, 8], validation [20] — центрирование 20 − 5 = 15; глобальное среднее 8 дало бы 12, это утечка.
- **Главная ошибка.** Отбирать признаки или масштабировать по всей таблице до cross-validation.

### [M05-L05. Анализ ошибок](lessons/M05-L05.md)

- **Правило.** Остаток e = ŷ − y; MAE — среднее модулей e, bias — среднее e; для каждого среза показывают размер, метрику и неопределённость.
- **Смысл величин.** bias — систематический сдвиг со знаком, MAE — величина ошибок; разнознаковые ошибки компенсируются в bias, но не в MAE.
- **Когда применять.** Чтобы превратить «модель ошибается» в проверяемую гипотезу. Пример: остатки [3, −3, 1, −1] дают bias = 0 и MAE = 2 — ошибки есть, но компенсируются.
- **Главная ошибка.** Править test под метрику или выводить причину ошибки из одной связи со срезом.

### [M05-L06. Обучить классификатор и выбрать правило решения](lessons/M05-L06.md)

- **Правило.** Pipeline: SimpleImputer, StandardScaler и OneHotEncoder, затем LogisticRegression; fit только на train, C и порог — на validation по заранее заданной стоимости; сохраняется pipeline вместе с порогом.
- **Смысл величин.** C — обратная сила регуляризации: меньше C — сильнее штраф; порог — правило решения; стоимость вида (2·FN + FP)/N задаёт цену ошибок; правило ничьей фиксируют до test.
- **Когда применять.** Чтобы получить воспроизводимое правило решения. Пример: при стоимости 2·FN + FP порог 0.3 даёт FN = 0, FP = 5, стоимость 5, а порог 0.6 — FN = 1, FP = 2, стоимость 4; выбирается 0.6, веса не меняются.
- **Главная ошибка.** Сохранить только веса без imputer, scaler, encoder и порога или подбирать порог по test.

### [M05-L07. Самостоятельный эксперимент на неоднородных данных](lessons/M05-L07.md)

- **Правило.** Признак допустим, только если известен в момент предсказания; разбиение одновременно по группам и по времени; группа, пересекающая границу, исключается целиком и записывается в excluded.
- **Смысл величин.** user_id — группа, day — момент события, review_score_after — поле из будущего; FitAudit записывает ID строк, реально переданных в fit.
- **Когда применять.** Для данных с повторными пользователями и временем. Пример: train до дня 10, validation до дня 20 — пользователь с днями [9, 12] пересекает первую границу, обе его строки уходят в excluded.
- **Главная ошибка.** Включать поле из будущего, даже переименованное, или делить строки одного пользователя между частями.

## M06. Проектирование ML-систем

### [M06-L01. Цель и ограничения](lessons/M06-L01.md)

- **Правило.** Требование = событие, единица, окно и способ расчёта; доля записывается с числителем и знаменателем; каждое число помечают как «измерено», «целевое» или «предположение».
- **Смысл величин.** Продуктовая метрика — цель пользователя, метрика содержания — корректность по рубрике, техническая — задержка и ошибки сервиса; ограничение отличается от пожелания тем, что его нарушение делает вариант неприемлемым.
- **Когда применять.** До выбора архитектуры. Пример: 291 из 300 запросов с HTTP 200 — 0.97; 45 корректных из 60 проверенных — 0.75; знаменатели разные, перемножать доли нельзя.
- **Главная ошибка.** Выдавать долю по маленькой проверенной выборке за качество всего продукта или целевое число за измеренное.

### [M06-L02. Контуры данных и модели](lessons/M06-L02.md)

- **Правило.** Выпуск = веса, preprocessing, feature_order, словари категорий, версии кода и данных; z = (x − μ)/s со статистиками train того же выпуска; указатель активного выпуска меняют только после контрольного запроса.
- **Смысл величин.** μ и s — среднее и масштаб train; manifest.json описывает состав выпуска; current.json указывает на активный выпуск; хеш подтверждает идентичность байтов, но не корректность сбора.
- **Когда применять.** При выпуске и загрузке модели. Пример: μ = 30, s = 6, w = 2, b = 1 — для x = 42 z = 2 и ответ 5; при подменённом s = 12 ответ 3, а вход x = 30 подмену не заметит.
- **Главная ошибка.** Проверять выпуск только на x = μ или обновлять статистики в сервисе отдельно от весов.

### [M06-L03. Batch и online](lessons/M06-L03.md)

- **Правило.** Начало обработки = max(приход, окончание предыдущего); задержка = окончание − приход; если поток выше скорости обслуживания, очередь растёт.
- **Смысл величин.** Batch считает ответы заранее для набора, online — после запроса; свежесть — возраст результата; ключ кэша включает версию модели, рубрику и состояние диалога; online learning — не online inference.
- **Когда применять.** При выборе режима и оценке ожидания. Пример: приходы [0, 1, 1.5] с, обслуживание 1 с, один исполнитель — окончания [1, 2, 3], задержки [1, 1, 1.5].
- **Главная ошибка.** Обещать отсутствие очереди по средней скорости за день или кэшировать ответ по ключу из одной последней фразы.

### [M06-L04. Наблюдение и изменение качества](lessons/M06-L04.md)

- **Правило.** Общая доля = сумма правильных / сумма проверенных; доли показывают по смысловым срезам вместе с числом примеров; data drift — изменение входов, concept drift — изменение связи входа и правильного ответа.
- **Смысл величин.** Лог — событие, метрика — агрегат, трассировка — шаги одного запроса; быстрые прокси (невалидный JSON, пустые ответы) ловят сбои рано, но не доказывают истинность ответа.
- **Когда применять.** Для мониторинга выпуска. Пример: X — RU 16/20 и EN 6/10, общая 22/30 ≈ 0.73; Y — RU 8/10 и EN 12/20, общая 20/30 ≈ 0.67: доли внутри языков те же, общая меняется из-за состава.
- **Главная ошибка.** Усреднять проценты без весов или считать любой drift ухудшением качества.

### [M06-L05. Отказы и откат](lessons/M06-L05.md)

- **Правило.** Повтор с тем же ключом (сессия и ход) возвращает прежний результат; результат устаревшего хода не показывают как актуальный; откат возвращает согласованный выпуск целиком и подтверждается контрольным сценарием.
- **Смысл величин.** Таймаут ограничивает ожидание, но не останавливает работу; shadow считает кандидата без показа, canary показывает его малой группе; fallback — заранее определённый честный ограниченный режим.
- **Когда применять.** Перед активацией кандидата и при сбое. Пример: эталон контрольного входа 12.5, кандидат дал 12.5000003 при допуске 1e−6 — принят; кандидат с другим preprocessing дал 9.0 — остаётся stable.
- **Главная ошибка.** Бесконечные повторы без ограничения или откат только весов с новыми статистиками preprocessing.

## M07. Нейросети и PyTorch

### [M07-L01. Линейный слой и нелинейность](lessons/M07-L01.md)

- **Правило.** Linear(a, b): Z = XWᵀ + b, weight формы [b, a], параметров a·b + b; ReLU(z) = max(0, z); два линейных слоя без активации сворачиваются в один: W₂W₁x + (W₂b₁ + b₂).
- **Смысл величин.** Logits — ненормированные оценки классов; softmax превращает их в положительные доли с суммой 1; CrossEntropyLoss ожидает logits и целочисленные номера классов.
- **Когда применять.** Чтобы оценить форму и размер сети до запуска. Пример: сеть 5→3→1 с bias — 5·3 + 3 = 18 и 3·1 + 1 = 4, всего 22 параметра, 88 байт в float32.
- **Главная ошибка.** Ставить softmax перед CrossEntropyLoss или считать logits вероятностями.

### [M07-L02. Autograd и обратный проход](lessons/M07-L02.md)

- **Правило.** Для ŷ = wx + b и L = (ŷ − y)²: ∂L/∂w = 2ex, ∂L/∂b = 2e, где e = ŷ − y; шаг w ← w − η·∂L/∂w; backward() добавляет производные в .grad.
- **Смысл величин.** requires_grad включает запись графа; zero_grad очищает накопленное; detach отделяет тензор от графа; item() извлекает число для журнала; no_grad отключает градиенты, eval() меняет поведение слоёв.
- **Когда применять.** Чтобы проверить autograd вручную. Пример: x = 1, y = 4, w = 2, b = 1 — e = −1, оба градиента −2; при η = 0.1 получаем w = 2.2, b = 1.2.
- **Главная ошибка.** Не обнулить градиенты перед независимым шагом или вызвать detach на пути, по которому нужен градиент.

### [M07-L03. Цикл обучения](lessons/M07-L03.md)

- **Правило.** Шаг: zero_grad, forward, loss, backward, step; loss эпохи = Σ(loss_batch·n_batch)/Σn_batch; validation — в eval() и без градиентов.
- **Смысл величин.** Батч — группа примеров для одного шага, эпоха — проход по train; лучший checkpoint — копия state_dict эпохи с лучшей validation; test оценивают один раз после выбора.
- **Когда применять.** Для любого цикла обучения. Пример: батчи размеров 5 и 1 со средними 0.2 и 0.8 — loss эпохи (1.0 + 0.8)/6 = 0.3, а не 0.5.
- **Главная ошибка.** Усреднять средние батчей одинаковым весом или выбирать эпоху по test.

### [M07-L04. Проверка и диагностика](lessons/M07-L04.md)

- **Правило.** Сначала симптом и минимальный воспроизводимый пример; подгонка 8–16 объектов проверяет вычислительный путь; NaN ищут по этапам — вход, logits, loss, градиенты — до первой нечисловой точки.
- **Смысл величин.** Недообучение — высокая ошибка и на train, и на validation; переобучение — train улучшается, validation ухудшается; clipping ограничивает норму градиента, но не устраняет причину.
- **Когда применять.** Когда обучение ведёт себя странно. Пример: validation [0.9, 0.7, 0.6, 0.58, 0.63, 0.7] при падающем train — берём checkpoint эпохи 4.
- **Главная ошибка.** Менять сразу несколько настроек или снижать learning rate, когда NaN уже есть во входе.

### [M07-L05. Сохранение и воспроизведение](lessons/M07-L05.md)

- **Правило.** Выпуск инференса = state_dict, config архитектуры, preprocessing и контрольные входы с ожидаемыми logits; загрузка — создать архитектуру, load_state_dict со strict, eval(), сравнить logits с допуском в новом процессе.
- **Смысл величин.** weights_only=True читает только тензоры; map_location='cpu' задаёт устройство; для продолжения обучения дополнительно нужны состояние оптимизатора, scheduler, номер шага и состояния RNG.
- **Когда применять.** Перед использованием сохранённой модели. Пример: mean = [4, 6], scale = [2, 3], W — единичная матрица, b = 0: raw [6, 12] даёт вход [1, 2] и logits [1, 2]; если scale потерян и стал [1, 1], logits [2, 6], max_abs_error = 4.
- **Главная ошибка.** Считать model.pt полным выпуском или проверять восстановление в том же ноутбуке со старым scaler.

## M08. NLP и Transformer

### [M08-L01. Текст и токены](lessons/M08-L01.md)

- **Правило.** Для next-token prediction последовательность [t₁ … tₙ] даёт input [t₁ … tₙ₋₁] и target [t₂ … tₙ]; лимит контекста считают в токенах конкретного токенизатора; корпус делят до нарезки окон.
- **Смысл величин.** ID — адрес строки таблицы embeddings, а не величина; EOS — конец последовательности, PAD — выравнивание, которое маска исключает из loss; UNK — явная политика для неизвестного символа.
- **Когда применять.** При подготовке данных для языковой модели. Пример: ID [7, 3, 9, 2] дают input [7, 3, 9] и target [3, 9, 2].
- **Главная ошибка.** Сравнивать длину строки в символах с лимитом токенов или делить корпус после нарезки перекрывающихся окон.

### [M08-L02. Embeddings](lessons/M08-L02.md)

- **Правило.** Таблица E формы [V, d]; ids формы [B, T] дают [B, T, d]; параметров V·d; cos(u, v) = u·v/(‖u‖·‖v‖).
- **Смысл величин.** Строка E — обучаемое представление токена; статический вектор одинаков для ID, контекстный зависит от окружения; косинус сравнивает направление и не определён для нулевого вектора.
- **Когда применять.** Для оценки памяти и сходства. Пример: V = 32 000, d = 256 — 8 192 000 параметров, около 32.8 MB в float32; cos([1, 2], [2, 4]) = 1, cos([1, 0], [0, 1]) = 0.
- **Главная ошибка.** Трактовать ID как координату смысла или включать PAD в среднее документа.

### [M08-L03. Attention](lessons/M08-L03.md)

- **Правило.** Q = XW_Q, K = XW_K, V = XW_V; S = QKᵀ/√d_k; A = softmax(S) по оси ключей; O = AV.
- **Смысл величин.** Q и K задают веса, V — содержимое; формы: Q и K [T, d_k], V [T, d_v], S и A [T, T], O [T, d_v]; каждая строка A в сумме даёт 1.
- **Когда применять.** Чтобы проверить attention вручную. Пример: d_k = 4, q = [2, 0, 0, 0], k₁ = [1, 0, 0, 0], k₂ = 0 — scores [1, 0], веса ≈ [0.731, 0.269]; при v₁ = 10, v₂ = 0 выход ≈ 7.31.
- **Главная ошибка.** Нормировать softmax по оси query или забыть деление на √d_k.

### [M08-L04. Позиции и causal mask](lessons/M08-L04.md)

- **Правило.** h_t = E[token_t] + P[t]; causal mask: позиция i видит ключи j ≤ i; запрещённые scores заменяют на −∞ до softmax.
- **Смысл величин.** Без позиций перестановка токенов только переставляет выходы; causal mask кодирует время, padding mask — отсутствие данных; диагональ разрешена.
- **Когда применять.** Для языковой модели, предсказывающей следующий токен. Пример: равные scores и V = [3, 6, 9] дают causal-выходы [3, 4.5, 6]; замена 9 на 90 меняет только третий выход — на 33.
- **Главная ошибка.** Обнулять scores будущего вместо −∞ (exp(0) = 1, доступ остаётся) или подменять causal mask маской padding.

### [M08-L06. Residual и LayerNorm: сохранить путь и выровнять масштаб](lessons/M08-L06.md)

- **Правило.** Residual h_new = h + F(h) при одинаковых формах; LayerNorm по признакам одной позиции: z_i = (x_i − μ)/√(v + ε), затем y_i = γ_i·z_i + β_i.
- **Смысл величин.** μ и v — среднее и средний квадрат отклонений с делением на число признаков, без n − 1; ε защищает от деления на ноль; γ и β обучаются.
- **Когда применять.** Чтобы проверить нормировку вручную. Пример: x = [1, 2, 6] — μ = 3, v = 14/3 ≈ 4.667, z ≈ [−0.926, −0.463, 1.389] при ε ≈ 0.
- **Главная ошибка.** Нормировать по позициям или по всему батчу вместо признаков одной позиции или складывать ветки разных форм.

### [M08-L07. Полный forward Transformer-блока](lessons/M08-L07.md)

- **Правило.** Pre-norm блок: u = x + Attention(LayerNorm₁(x)), y = u + MLP(LayerNorm₂(u)); MLP — Linear D→H, GELU, Linear H→D.
- **Смысл величин.** Attention смешивает позиции с учётом маски, MLP обрабатывает каждую позицию отдельно одними весами; выходы голов склеиваются: [B, h, T, d_k] → [B, T, h·d_k], затем выходной Linear.
- **Когда применять.** Чтобы проследить формы и размер блока. Пример: D = 16, H = 64 — в MLP 16·64 + 64 + 64·16 + 16 = 2128 параметров; при B = 3, T = 7 формы [3, 7, 16] → [3, 7, 64] → [3, 7, 16].
- **Главная ошибка.** Считать одинаковую форму выхода признаком одинакового действия блоков или складывать выходы голов вместо склеивания.

### [M08-L05. Мини-языковая модель](lessons/M08-L05.md)

- **Правило.** P(x₁ … x_T) = Π P(x_t ∣ x_<t); loss — среднее −ln вероятности правильного токена; perplexity = exp(loss); для равномерного словаря из V токенов loss = ln V, perplexity = V.
- **Смысл величин.** Loss и perplexity зависят от токенизатора и корпуса; teacher forcing подаёт правильный префикс, свободная генерация — собственные выходы модели; unigram baseline не использует контекст.
- **Когда применять.** Для оценки языковой модели. Пример: вероятности правильных токенов [0.6, 0.3, 0.1] дают NLL ≈ 1.339 и perplexity ≈ 3.82, хотя средняя вероятность ≈ 0.333.
- **Главная ошибка.** Сравнивать loss моделей с разными токенизаторами или принимать удачную генерацию одной фразы за validation.

## M09. Применение и запуск LLM

### [M09-L01. Сообщения и шаблон диалога](lessons/M09-L01.md)

- **Правило.** messages → apply_chat_template(…, add_generation_prompt=True) → ID; шаблон берут из tokenizer той же модели и ревизии; special tokens после шаблона повторно не добавляют.
- **Смысл величин.** system, user, assistant — соглашение интерфейса: после шаблона это токены одной последовательности; add_generation_prompt добавляет начало нового ответа assistant; tokenize=False показывает фактическую строку.
- **Когда применять.** При каждом вызове чат-модели и при разборе неожиданного ответа. Пример учебного шаблона `<role>text</role>`: messages [user «Hi»] с add_generation_prompt дают `<user>Hi</user><assistant>`, и ответ модели начнётся после `<assistant>`.
- **Главная ошибка.** Приклеивать маркеры другой модели или передавать только последний ответ без вопроса, к которому он относится.

### [M09-L02. Контекст и история](lessons/M09-L02.md)

- **Правило.** N_prompt + N_new ≤ C, где N_prompt считают после окончательного шаблона; старые пары удаляют целиком, обязательные части сохраняют; если не помещается обязательная часть — явная ошибка.
- **Смысл величин.** C — лимит контекста модели и исполнения; N_prompt — инструкции, история, источники, вопрос и служебные маркеры; N_new — резерв генерации; контекст не меняет веса, а сохранённое в базе модель не видит без передачи.
- **Когда применять.** Перед каждым generate и при сборке RAG-запроса. Пример: C = 512, prompt 60 + 180 + 200 + 40 + 20 = 500, резерв 64 — нужно 564, превышение 52; удаление старой пары из 80 токенов даёт 484.
- **Главная ошибка.** Забыть служебные маркеры и резерв ответа или считать лимит по символам.

### [M09-L03. Генерация и ограничения](lessons/M09-L03.md)

- **Правило.** p_i ∝ exp(z_i/T); top-k оставляет k самых вероятных токенов, top-p — минимальный отсортированный префикс с суммой ≥ p; оставшиеся вероятности перенормируют.
- **Смысл величин.** T > 1 выравнивает распределение, 0 < T < 1 заостряет; greedy (do_sample=False) берёт argmax, параметры sampling не действуют; max_new_tokens ограничивает только новые токены; seed фиксирует генератор, но не гарантирует побитовую воспроизводимость между версиями.
- **Когда применять.** При выборе настроек генерации и их сравнении на фиксированном наборе запросов. Пример: logits [2, 1, 0] при T = 1 дают ≈ [0.665, 0.245, 0.090], при T = 0.5 — ≈ [0.867, 0.117, 0.016]; для [0.6, 0.25, 0.1, 0.05] top-k = 2 даёт ≈ [0.7059, 0.2941].
- **Главная ошибка.** Считать низкую temperature гарантией правильности или сравнивать один удачный sampling с одним greedy.

### [M09-L04. Локальный инференс и память](lessons/M09-L04.md)

- **Правило.** Память весов ≈ N·b; KV-cache ≈ 2·L·T·H_kv·D_head·b·B; квантование q = round(w/s), ŵ = s·q; token/s = новые токены / время вызова, s/token — обратная величина.
- **Смысл величин.** N — число параметров, b — байт на элемент (float32 — 4, float16 — 2, int8 — 1); 2 — ключи и значения, L — слои, T — длина, H_kv — KV-головы, D_head — размер головы, B — сессии; s — масштаб; обе скорости включают prefill и не являются TTFT.
- **Когда применять.** Чтобы оценить, поместится ли модель, и честно подписать скорость. Пример: 135 млн параметров — 540 MB во float32 и 270 MB во float16; L = 12, T = 512, H_kv = 4, D_head = 16, b = 4, B = 1 — кэш 3 145 728 байт = 3 MiB; w = 0.26 при s = 0.1 даёт q = 3, ŵ = 0.3, ошибку 0.04.
- **Главная ошибка.** Сравнивать с объёмом RAM только размер файла или выдавать новые токены / полное время за скорость decode и TTFT.

### [M09-L05. Контракт ответа](lessons/M09-L05.md)

- **Правило.** Ответ модели — недоверенный вход: синтаксис (весь текст — один JSON-объект), схема (ровно feedback и score), смысл (рубрика и источники), актуальность хода; нарушение — отдельное состояние, конечный повтор и fallback.
- **Смысл величин.** feedback — непустая строка; score — целое 0, 1 или 2 с проверкой type(score) is int, потому что isinstance(True, int) истинно; состояния invalid_json, wrong_keys, empty_feedback, score_out_of_range; таймаут и пустой вывод — не оценка кандидата.
- **Когда применять.** Перед показом результата модели пользователю или передачей его в код. Пример: {"feedback": "Explain isolation", "score": 1} принимается, {"feedback": "OK", "score": true} и {"feedback": "", "score": 2} отклоняются.
- **Главная ошибка.** Ставить score 0 при таймауте или пустом выводе либо принимать true вместо целого балла.

### [M09-L06. Выбрать локальную конфигурацию по измерениям](lessons/M09-L06.md)

- **Правило.** Каждую конфигурацию запускают в новом процессе с одинаковыми revision, tokenizer, запросами, greedy, лимитом новых токенов, потоками и прогревом; размер артефакта, RSS, пик, время, токены и текст ответов записывают раздельно; решение — по правилу, выбранному до запуска.
- **Смысл величин.** Размер состояния — torch.save конкретного артефакта со служебными данными; RSS — сумма рабочей памяти дерева процессов, общие страницы могут учитываться дважды; пик — замеры каждые 30 мс; dynamic int8 квантует Linear-слои, остальные части не обязаны стать int8.
- **Когда применять.** При выборе между float32 и int8 или другим runtime. Пример: 40 токенов за 10 с — 4 token/s и 0.25 s/token; 32 токена за 9 с — ≈ 3.56 token/s: меньшее полное время не означает большую скорость токенов.
- **Главная ошибка.** Объявлять квантование лучше по одной скорости или выдавать размер файла за пик RAM.

## M10. RAG и поиск

### [M10-L01. Документ и фрагмент](lessons/M10-L01.md)

- **Правило.** Chunk — единица индекса и выдачи: целая смысловая часть (предложение, абзац, раздел) с id, document_id, version, источником и диапазоном; изменился текст — пересчитай embedding и атомарно переключи индекс; удалённый документ исчезает из выдачи.
- **Смысл величин.** Документ — исходник, chunk — фрагмент для поиска; overlap — повтор соседнего текста: сохраняет связь на границе, но растит индекс и даёт почти дубли, которые не являются независимыми подтверждениями; хеш содержимого ловит изменение, но не проверяет смысл.
- **Когда применять.** При подготовке и обновлении базы RAG. Пример: документ из 500 слов, окно 200 и overlap 50 (шаг 150) — фрагменты [0, 200), [150, 350), [300, 500); в индексе 600 слов вместо 500, на 20% больше, и каждая граница повторена дважды.
- **Главная ошибка.** Резать посреди условия («не» и остальная часть в разных фрагментах) или индексировать новый текст со старым embedding.

### [M10-L02. Лексический и векторный поиск](lessons/M10-L02.md)

- **Правило.** IDF(t) = ln((1 + n)/(1 + df_t)) + 1 (scikit-learn со smoothing); Recall@k = число релевантных в top-k / число всех релевантных; Precision@k = число релевантных в top-k / k; пересечение считают по уникальным ID.
- **Смысл величин.** n — число документов, df_t — сколько документов содержат термин; TF-IDF даёт разреженный вектор, encoder — плотный; cosine — относительная близость в данном корпусе, а не вероятность правильного ответа; при пустой разметке recall не определён.
- **Когда применять.** При сравнении retriever до генерации на одних query_id. Пример: n = 9, термин в 2 документах — IDF = ln(10/3) + 1 ≈ 2.204; gold = {A, B, C}, top-4 = [B, X, C, Y] — Recall@4 = 2/3 ≈ 0.667, Precision@4 = 2/4 = 0.5.
- **Главная ошибка.** Назвать cosine вероятностью правильного ответа или считать LSA pretrained семантической моделью.

### [M10-L03. Гибридный поиск и reranking](lessons/M10-L03.md)

- **Правило.** RRF: score(d) = Σ_r 1/(c + rank_r(d)), ранги с 1, отсутствующий в списке документ вклада не получает, ничья — по ID; reranker пересматривает только top-N; MRR — среднее 1/rank первого релевантного, 0 если он не найден.
- **Смысл величин.** c > 0 сглаживает разницу верхних позиций и фиксируется до test; candidate Recall@N — попал ли нужный chunk в пул второй стадии, MRR — насколько высоко он после reranking; cross-encoder оценивает пару запрос–документ вместе, поэтому дорог и работает на top-N.
- **Когда применять.** При объединении lexical и dense и выборе N. Пример: L = [P, Q, R], D = [R, S, P], c = 1 — P = 1/2 + 1/4 = 0.75, R = 1/4 + 1/2 = 0.75, Q = S = 1/3; по ID порядок [P, R, Q, S]; первые релевантные на местах 2, 1 и 4 дают MRR = (0.5 + 1 + 0.25)/3 ≈ 0.583.
- **Главная ошибка.** Складывать scores разных методов напрямую или ждать, что reranker поднимет chunk, которого нет в top-N.

### [M10-L04. Контекст и подтверждение ответа](lessons/M10-L04.md)

- **Правило.** Три разные проверки: ID существует → документ релевантен теме → фрагмент подтверждает конкретное утверждение; ответ делят на атомарные утверждения и каждому ставят supported, contradicted или insufficient; при недостатке оснований — явный отказ.
- **Смысл величин.** supported — фрагмент говорит это с теми же условиями; contradicted — утверждает обратное; insufficient — молчит; «может» нельзя усиливать до «всегда»; инструкция внутри документа — данные, а не команда; порог similarity не универсален и выбирается на development.
- **Когда применять.** При проверке ответа RAG перед показом. Пример: источник «Кэш уменьшает задержку повторных чтений и может отдать устаревшие данные» — «кэш может вернуть устаревшие данные» supported, «кэш всегда возвращает свежие данные» contradicted, «кэш снижает стоимость сервера» insufficient.
- **Главная ошибка.** Проверить только существование ID или считать молчание источника подтверждением отрицания.

### [M10-L05. Диагностика и обновления](lessons/M10-L05.md)

- **Правило.** Идти по трассе: источник есть в корпусе → условие сохранила нарезка → chunk в кандидатах → прошёл reranking → вошёл в контекст → модель его использовала; исправлять самый ранний достаточный дефект, менять один компонент за раз и повторять весь фиксированный набор.
- **Смысл величин.** Версия RAG — корпус, нарезка, encoder и его revision, индекс, параметры поиска, reranker, генератор, template и рубрика; oracle context — ручная подстановка верного фрагмента для диагностики, а не метрика поиска; ключ кэша включает версии корпуса и модели.
- **Когда применять.** При разборе ошибки RAG. Пример: chunk G:2 с нужным условием стоит в кандидатах вторым, после reranking — пятым, а в контекст берут top-3: первый дефект на reranking; проверка — тот же набор с другим reranker или top-5 при прежних остальных компонентах.
- **Главная ошибка.** Менять все этапы одновременно или выдавать oracle-метрику за качество автоматического поиска.

### [M10-L06. Диагностировать русский RAG по трассе ошибки](lessons/M10-L06.md)

- **Правило.** Метрики считают на трёх уровнях: документ (Recall@k по уникальным document_id), chunk (дошло ли условие до переданных фрагментов), утверждение (claim → source); для вопроса без ответа Recall = None — его исключают из среднего и отдельно считают правильные отказы с явным знаменателем.
- **Смысл величин.** Document Recall@3 = 1 не гарантирует, что подтверждающая фраза дошла до генератора; obsolete-версия нужна для воспроизведения, а не для актуального поиска; порог отказа 0.12 — baseline, заданный до check; проверка наличия фразы — учебный proxy.
- **Когда применять.** При оценке RAG на русском наборе. Пример: четыре answerable-вопроса с recall 1, 1, 0.5 и 0 и два без ответа, из них один верный отказ: средний recall = 2.5/4 = 0.625, а не 2.5/6 ≈ 0.417; правильных отказов 1/2.
- **Главная ошибка.** Усреднять None как 0, держать старую версию в актуальном поиске или выдавать близость векторов за доказательство утверждения.
