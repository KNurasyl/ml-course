# P05 Первая архитектура ML сервиса

Занятие P05, версия 1.1.0. Это учебный материал, а не отметка о прохождении. Работа выполняется локально на CPU; платные сервисы не нужны.

Практический файл: [ноутбук P05](../../notebooks/pilot/P05.ipynb). После самостоятельной попытки можно свериться с [эталоном P05](../../solutions/pilot/P05.ipynb). Проверь текстовые ответы и рассуждения по критериям и ключу после своей попытки. Успешный запуск ноутбука сам по себе не подтверждает понимание. Порядок самопроверки описан в руководстве по самостоятельному обучению.

Начальный ориентир занятия — около четырёх часов вместе с перерывами: восстановление предыдущей темы, объяснение, вычисления вручную, лабораторная, самостоятельная задача и разбор. Если необходимая предпосылка не усвоена, сначала выполни корректирующее упражнение. Дополнительный пятый час оставь для завершения работы или спокойного повторения.

Режим AI: первую самостоятельную попытку сделай без готового решения. После неё разрешены подсказки и объяснения. Запиши, какая помощь потребовалась. Полный разбор допустим, но после него самостоятельность проверяется другим примером. Записывай собственное время и не торопись: цель занятия — получить навык, который можно объяснить и воспроизвести.

Сегодня ты опишешь путь от запроса до ответа, задашь контракт вычисления, согласуешь версию модели с подготовкой входа и разберёшь один отказ. ## Проверь себя сначала

**Короткий путь для знакомой темы, 2–5 минут.** Версия v2: ŷ = 3(x − 5) + 2, центр 5 хранится в артефакте вместе с весом и bias. Вычисли ответ для x = 7. Какой ответ получится, если вес и bias взять из v2, а центр — из v1, где он равен 3?

Запиши ответ и объяснение, затем сверь с [ключом P05-D](../../solutions/pilot/answer-key.md#p05-d). Всё верно и объяснение совпадает по смыслу — переходи сразу к самостоятельной работе P05-HW01, затем к новому варианту. Ошибка, сомнение или ответ без объяснения — проходи урок полностью с начала. ## Почему формулы недостаточно для сервиса

Функция predict отвечает только на вопрос вычисления. Пользовательский сервис должен ещё получить корректные данные, выбрать нужную версию параметров, обработать ошибку и вернуть понятный результат. Даже идеальная формула не помогает, если система перепутала единицы измерения или применила преобразование от другой версии.

Схема первого сервиса состоит из входного запроса, проверки, подготовки признаков, модели и формирования ответа. Параметры модели загружаются из артефакта. Артефакт — сохранённый результат обучения вместе с минимальной информацией, необходимой для использования: формула или тип модели, параметры, ожидаемые признаки и версия. Если модель обучалась на центрированных признаках, среднее преобразования относится к тому же артефакту.

Отдельная часть схемы — процесс обучения. Он читает обучающие данные, подбирает параметры и формирует новый артефакт. Онлайн-запрос пользователя в нашем первом сервисе этот процесс не запускает. Такое разделение облегчает отладку: можно отдельно спросить, правильны ли параметры и правильно ли приложение их использует.

## Разобранный контракт

Запрос содержит поле x с конечным числом. Для версии v1 параметры равны w = 2, b = 1. Вход x = 4 должен вернуть prediction = 9 и model_version = v1. Поле версии необходимо, чтобы понять, какой именно артефакт породил результат. Без него сравнение ответов до и после обновления становится ненадёжным.

Строка «4» в этом контракте не является числом. Отсутствующее поле нельзя молча заменить нулём: клиент мог ошибиться, и ответ на другую задачу будет выглядеть успешным. NaN и бесконечность тоже отвергаются, иначе они распространятся по вычислению и разрушат смысл метрики. Правила здесь выбраны специально для учебного интерфейса; другой продукт может использовать иные правила, но обязан обозначить их явно.

Версия v2 с w = 3, b = 2 для того же входа даст 14. Это не обязательно улучшение. Чтобы выбрать версию, нужна отдельная проверка качества. Выдача большего числа сама по себе не является успехом. Механизм переключения версий и доказательство полезности модели решают разные задачи.

## Практика с поддержкой

Нарисуй две дорожки: обучение и обработка запроса. Соедини их только через сохранённый артефакт. В ноутбуке проследи локальный обработчик на корректном входе. Затем последовательно передай строку, отсутствующее поле и не конечное число. Для каждого случая запиши, какой этап обязан его обнаружить.

Добавь к технической записи запроса идентификатор, время обработки и версию модели. Для учебной задачи достаточно измерения локального вызова. Не делай вывод о поведении под реальной нагрузкой из одного быстрого запуска: измерения маленькой функции и работа сетевого сервиса имеют разные границы.

## Самостоятельная работа P05-HW01

Подготовь краткий документ интерфейса: допустимый вход, успешный ответ, ошибочные входы и место хранения версии. Рассчитай ответ v2 на x = 4. Опиши процедуру возврата на v1, если после обновления проверка выявила ухудшение.

Затем разбери отказ: параметры загружены из новой версии, а среднее для центрирования осталось от старой. Объясни, почему вычисление может завершаться без исключения, но давать неверный ответ. Предложи одну проверку, которая обнаружит несогласованный артефакт до обработки пользовательских запросов.

Сохрани схему, таблицу четырёх входных случаев и описание отказа в своей работе. Не рисуй очередь, кластер и распределённую базу только потому, что они встречались в вакансиях. Каждый компонент должен отвечать на понятную потребность этой задачи.

## Подсказки и проверка

Подсказка 1: для каждого блока укажи вход и выход. Подсказка 2: выясни, какие числа были получены при обучении и должны загружаться вместе. Подсказка 3: пропусти через весь путь один заранее проверенный пример и сравни ожидаемый ответ.

Работа подтверждает навык, если обучение отделено от применения, контракт однозначен, версия прослеживается и найден конкретный механизм ошибки. Фраза «добавить мониторинг» без объяснения наблюдаемого сигнала недостаточна.

Повторная попытка использует вход в миллисекундах вместо секунд: найти несоответствие единиц и показать место исправления. Отложенная проверка добавит второй признак: придётся обновить контракт, артефакт и проверочные примеры согласованно. Эти же вопросы вернутся для LLM, поиска и голосового сервиса.
