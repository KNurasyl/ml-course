# P03 Как проверять модель на новых данных

Занятие P03, версия 1.1.0. Это учебный материал, а не отметка о прохождении. Работа выполняется локально на CPU; платные сервисы не нужны.

Практический файл: [ноутбук P03](../../notebooks/pilot/P03.ipynb). После самостоятельной попытки можно свериться с [эталоном P03](../../solutions/pilot/P03.ipynb). Проверь текстовые ответы и рассуждения по критериям и ключу после своей попытки. Успешный запуск ноутбука сам по себе не подтверждает понимание. Порядок самопроверки описан в руководстве по самостоятельному обучению.

Начальный ориентир занятия — около четырёх часов вместе с перерывами: восстановление предыдущей темы, объяснение, вычисления вручную, лабораторная, самостоятельная задача и разбор. Если необходимая предпосылка не усвоена, сначала выполни корректирующее упражнение. Дополнительный пятый час оставь для завершения работы или спокойного повторения.

Режим AI: первую самостоятельную попытку сделай без готового решения. После неё разрешены подсказки и объяснения. Запиши, какая помощь потребовалась. Полный разбор допустим, но после него самостоятельность проверяется другим примером. Записывай собственное время и не торопись: цель занятия — получить навык, который можно объяснить и воспроизвести.

## Результаты и вход

Ты научишься разделять данные для подбора и проверки, обнаруживать использование будущей информации и применять преобразование, рассчитанное только на обучающей части. Нужны P01–P02, среднее и чтение небольшого списка. Полную теорию вероятностей для этого урока знать не требуется.

## Две разные роли данных

Обучающие примеры помогают выбрать параметры. Проверочные примеры помогают увидеть поведение на данных, которые не участвовали в этом выборе. Если многократно менять решение после просмотра проверочного результата, этот набор постепенно становится частью настройки. Название переменной test само по себе не защищает независимость проверки.

Позже мы будем использовать три роли: train для обучения параметров, validation для выбора подхода и test для окончательной оценки уже зафиксированного решения. Пока важно понять общий принцип. Информация из будущей проверки не должна помогать вычислению, которое мы потом называем независимым испытанием.

Утечка бывает заметной, например правильный ответ случайно попал во входные признаки. Бывает менее очевидной: среднее для заполнения пропусков рассчитали по всей таблице до разделения. Даже если метки не использовались, обработка уже увидела распределение отложенных данных. Насколько это изменит численную метрику, зависит от задачи; наличие неправильного процесса не следует оправдывать удачным результатом одного запуска.

## Разобранный пример

Обучающие входы равны [0,1,2], ответы — [1,3,5]. Отложенные входы равны [3,4], ответы — [7,9]. Формула 2x + 1 точна для этой искусственной зависимости. Среднее обучающих входов равно 1. Если центрировать данные по этому среднему, обучение получает [-1,0,1], а отложенная часть — [2,3].

Если ошибочно рассчитать среднее по всем пяти входам, получится 2. Тогда обучающая часть станет [-2,-1,0], а отложенная — [1,2]. Само число 2 не является неправильным средним всей таблицы. Ошибка заключается в том, что сведения из отложенной части участвовали в подготовке обучающего преобразования.

Для выражения исходной функции через z = x − 1 требуется prediction = 2z + 3. Если заменить среднее на 2, сохранив параметры, предназначенные для z = x − 1, предсказания изменятся. Поэтому версия модели должна храниться вместе с согласованным преобразованием. Это первый мост к системному дизайну.

## Практика с поддержкой

Раздели таблицу по заранее заданным индексам. Рассчитай среднее только по train, затем примени одно и то же преобразование к обеим частям. В отчёте подпиши, на каких строках выполнялся fit и к каким строкам применялся transform. Посчитай ответы модели и MSE для отложенной части.

После этого намеренно создай неправильный вариант со средним всей таблицы. Объясни отличие процессов. Не делай вывод «утечка всегда улучшает метрику»: в конкретной искусственной задаче она может ухудшить результат, ничего не изменить или исказить сравнение иным способом.

## Самостоятельная работа P03-HW01

Получи новый набор: train x = [1,2,3], y = [3,5,7]; test x = [4,5], y = [9,11]. Рассчитай среднее train, преобразуй обе части и запиши формулу, сохраняющую предсказания 2x + 1 в новых координатах. Отдельно укажи ошибочное среднее всей таблицы.

Разбери ещё два случая. В таблице есть несколько реплик одного разговора, и строки случайно распределены между train и test. Вторая таблица содержит измерения по времени, но в обучение попали записи, сделанные после тестового периода. Для каждого случая объясни, какая зависимость может сделать результат слишком оптимистичным, и предложи единицу разделения.

## Подсказки и характерные ошибки

Подсказка 1: для каждого вычисляемого числа спроси, откуда оно получено. Подсказка 2: отдели создание преобразования от его применения. Подсказка 3: подставь x = z + mean в исходную формулу и упрости выражение.

Частая ошибка — использовать разные средние отдельно для train и test. Тогда координаты двух частей имеют разный смысл. Другая ошибка — думать, что случайное перемешивание всегда лучше временного разделения. Выбор зависит от того, какие будущие случаи должна представлять проверка.

## Критерии и следующая попытка

Работа принимается, если обучающее преобразование не использует test, формула в новых координатах сохраняет ответы и объяснён смысл группового или временного разделения. Критическая ошибка — настраивать решение по окончательному тесту, продолжая называть его независимым.

Повторная попытка: train x = [2,4,6], test x = [8,10], исходная функция 3x − 1. Через несколько занятий проверь тот же принцип для диалогов интервьюера: все связанные реплики одной сессии должны рассматриваться совместно при выборе независимой проверки.

Основной источник для углубления: [scikit-learn о типичных ошибках и утечке](https://scikit-learn.org/stable/common_pitfalls.html). Подробнее о разделении: [cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html).
