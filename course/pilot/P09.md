## Результаты и необходимые знания

Задача занятия — собрать небольшой эксперимент, где другой человек может повторить результат, а вывод следует из честного сравнения. Ты должен разделить роли данных, построить простой baseline, сравнить кандидатов на validation и применить окончательный тест после фиксации решения. Требуются все предыдущие вычислительные темы; новой большой математической теории здесь нет.

## Что именно сравнивается

Baseline — простое исходное решение, с которым имеет смысл сравнить более сложное. Для числового прогноза можно всегда возвращать среднее обучающих ответов. Это не хорошая модель для любой задачи, но полезная точка отсчёта. Если сложное решение не выигрывает у такого baseline, сначала нужно понять причину, а затем добавлять компоненты.

В эксперименте фиксируются данные, разделение, модели, метрика и порядок действий. Случайный seed позволяет повторить конкретную генерацию и перемешивание, но не делает результат статистически надёжным автоматически. Можно воспроизводимо получить плохой эксперимент. Проверка процесса и воспроизводимость дополняют друг друга.

Обучение подбирает параметры по train. Validation используется для выбора кандидата. Test остаётся для оценки уже выбранного решения. Если после просмотра test ты исправил признаки или выбрал новую модель, нужно честно признать, что этот тест участвовал в разработке, и предусмотреть новую независимую проверку.

## Маленький разобранный пример

Возьмём шесть искусственных строк x от 0 до 5 и ответы [1,4,4,7,10,10]. Первые четыре строки считаем обучающими, пятую — validation, шестую — test. Среднее обучающих ответов равно 4, поэтому baseline всегда выдаёт 4. Линейная модель, найденная методом наименьших квадратов по этим четырём строкам, имеет w = 1.8 и b = 1.3.

На validation при x = 4 baseline ошибается на −6, его квадрат ошибки равен 36. Линейная модель выдаёт 8.5, её квадрат ошибки равен 2.25. Если выбрать линейную модель по этому сравнению, для x = 5 она выдаст 10.3, а квадрат ошибки на test будет 0.09.

Этот пример позволяет проследить роли данных, но одна проверочная строка слишком мала для содержательного вывода о реальной надёжности. Поэтому в кодовой лабораторной используется отдельный набор из ста строк. Маленькая таблица не смешивается с ним.

## Данные лабораторной

Генератор NumPy создаётся через default_rng(2026). Сначала он создаёт сто x из равномерного распределения от −2 до 2, затем сто шумовых значений из нормального распределения со средним 0 и стандартным отклонением 0.35. Ответы вычисляются как 2x+1+noise. Затем тот же генератор создаёт перестановку ста индексов: первые 60 относятся к train, следующие 20 к validation, последние 20 к test.

Порядок вызовов важен для точного воспроизведения. В отчёте нужно сохранить правило генерации, seed и индексы разделения. Эти данные синтетические: они полезны для проверки метода, но не являются доказательством качества будущего интервьюера.

## Практика с поддержкой

Обучи baseline средним train_y и линейную регрессию только на train. Сначала получи validation MSE двух кандидатов. Зафиксируй выбор в отдельной записи и только после этого посмотри test выбранного решения. Сохрани параметры, версии зависимостей и таблицу результатов.

Восстанови эксперимент в новом процессе или после перезапуска ядра ноутбука. Если результат отличается, проверь порядок генерации, скрытые переменные, индексы и версии. Объясни, какие различия допустимы из-за численной арифметики, а какие означают другой эксперимент.

## Самостоятельная работа P09-HW01

Создай самостоятельный вариант набора: seed = 2026, стандартное отклонение шума = 0.7. Остальные условия сохрани: сто x из uniform(−2,2), затем normal(0,0.7), ответы 2x+1+noise, затем перестановка тем же генератором и разделение 60/20/20. Это отдельный эксперимент после практики с шумом 0.35. Заново обучи baseline и линейную модель только на train, зафиксируй выбор по validation и затем оцени выбранную модель на test.

Подготовь отчёт с целью, baseline, двумя кандидатами, правилом разделения, validation-результатами, зафиксированным выбором и test-результатом. Разбери минимум три индивидуальных ошибки выбранной модели: вход, ответ, предсказание, отклонение. Сравни результат с практикой и объясни, что именно изменилось при увеличении шума.

Затем намеренно создай ошибочный вариант, в котором среднее baseline берётся по всем ответам. Обозначь его как демонстрацию нарушения, а не ещё один допустимый кандидат. Укажи, почему небольшая разница метрик не оправдывает использование test_y.

## Проверка и перенос

Подсказка 1: нарисуй, какие строки доступны каждому шагу. Подсказка 2: вынеси выбор кандидата до просмотра test. Подсказка 3: перезапусти весь процесс и сравни артефакты.

Критическая ошибка — выбирать по test и затем публиковать его метрику как независимую. Самостоятельность подтверждается воспроизводимым запуском, корректной хронологией выбора и объяснением ограничений данных.

Повторная попытка использует новый seed 2028 и шум 0.7 при прежнем правиле эксперимента. Отложенная проверка использует seed 2029 и новый уровень шума 1.0: сравни, что изменилось в ошибках, сохраняя честный процесс. Поскольку изменены и шум, и случайная выборка, не приписывай точную разницу метрик одному фактору. Источники: [scikit-learn Cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html), [NumPy Generator](https://numpy.org/doc/stable/reference/random/generator.html).
