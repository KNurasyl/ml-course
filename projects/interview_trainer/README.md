# Эталон: локальный голосовой тренажёр

Версия 1.1.0. Это отдельная учебная реализация для разбора после собственной попытки M16. В ней есть HR и backend сценарии по четыре темы, каждая допускает одно уточнение: от четырёх до восьми ответов. Переходы задаёт явное состояние Python; настоящая Qwen2.5-0.5B-Instruct на CPU выбирает фрагмент ответа, критерий и следующий учебный вопрос из ограниченного набора. Приложение показывает дословную цитату и нейтральную формулировку по рубрике. Это ограниченный модельный выбор с программной проверкой, а не свободная экспертная оценка кандидата. Технический сценарий передаёт найденные источники. Vosk распознаёт речь, Windows SAPI озвучивает текст. Платных API нет.

## Разбор проекта (черновик статьи, расширение 1.2.0)

Связный разбор для портфолио — [docs/interview-trainer-writeup.md](../../docs/interview-trainer-writeup.md): задача, архитектура со схемой, оценки, компромиссы, отрицательные результаты и что дальше. Черновик не опубликован, все числа в нём ссылаются на файлы `quality/`. Главное:
- выбор из вариантов вместо свободного отзыва убрал критические ошибки (4 из 8 → 0 из 8) и ускорил ответ в 3–5 раз, но порог полезности M11 не проходит ни 0.5B, ни 4B;
- узкое место 4B — короткий список следующих шагов и маленький корпус, а не размер модели;
- LLM-судья не заменяет разметку (каппа −0.20 и 0.18), а экранирование данных не останавливает убеждение без входного фильтра.

## Запуск

Из папки курса в PowerShell:

```powershell
Set-Location C:\projects\ml-llm-course
.\.venv\Scripts\python.exe tools\download_models.py --speech --llm
.\.venv\Scripts\python.exe -m projects.interview_trainer.app
```

Открой http://127.0.0.1:8765 в Edge. Выбери направление, нажми «Начать интервью». «Озвучить вопрос» запускает местный русский голос. «Записать голос» просит доступ к микрофону; «Закончить запись» отправляет WAV в локальный распознаватель. Сначала проверь распознанный текст, затем отправь ответ. Можно вводить ответ с клавиатуры. «Прервать голос» останавливает воспроизведение и игнорирует результат ещё не завершённого запроса синтеза. Первый ответ загружает LLM, поэтому его время включает холодный старт.

Скачивание нужно один раз; на этом ноутбуке модели уже загружены. LLM занимает около 1 ГБ на диске, речь — десятки МБ; дополнительная M09 использует отдельную модель. Версии моделей зафиксированы в [reference-models.json](../../metadata/reference-models.json). После установки и скачивания сервер работает без сети. Исходные ссылки используются только при открытии источников человеком. Для восстановления Python-окружения: `tools/bootstrap.ps1`.

Выход: Ctrl+C в окне PowerShell. Сервер слушает только 127.0.0.1. Порт можно изменить `--port 8766`. При сообщении о занятом порте не останавливай незнакомый процесс: выбери другой порт.

## Что происходит в запросе

```text
Микрофон → PCM WAV → Vosk → редактируемый текст
                                     ↓
Состояние интервью → вопрос → поиск → контекст → Qwen → обратная связь
                    ↓
               Windows SAPI → WAV → воспроизведение / отмена
```

В `core.py` живут темы, уточнения, проверка номера хода и поиск. `feedback.py` отделяет raw_output от разрешённого display_text. `llm.py` загружает pinned snapshot локально и ограничивает вход 1800 токенами; обычный baseline использует лимит128, JSON-вариант192, bounded choice — длину допустимой комбинации плюс EOS. `speech.py` проверяет mono PCM16 16 kHz. `app.py` соединяет этапы через HTTP; одновременно выполняется одна тяжёлая операция, второй запрос получает409. Браузер записывает поток через AudioWorklet, однако основной UI распознаёт целые реплики. Отдельная обязательная лабораторная M15-L06 показывает настоящий incremental ASR, сегментацию пауз и отменяемую очередь фрагментов; она не является автоматически включённым streaming-режимом UI.

Ответы хранятся в памяти процесса. Кнопка экспорта сохраняет сессию JSON по действию пользователя; перезапуск сервера удаляет несохранённые сессии. Идентификатор текущей сессии хранится в sessionStorage вкладки; «Восстановить сессию» получает актуальное состояние после потери HTTP-ответа или обновления вкладки. Эта кнопка не восстанавливает данные после перезапуска сервера. Временные WAV удаляются после распознавания или отправки синтеза. Консоль не печатает содержание интервью. Не отправляй личные сведения, которые не нужны для учебной задачи.

По умолчанию тренажёр распознаёт речь через Vosk и озвучивает через Windows SAPI. Сравнение конфигураций и его границы разобраны в уроке M15-L07X: авторский замер сделан на синтетическом голосе.

## Профили моделей (расширение 1.2.0)

```powershell
.\.venv\Scripts\python.exe -m projects.interview_trainer.profiles list
.\.venv\Scripts\python.exe -m projects.interview_trainer.app --profile strong
.\.venv\Scripts\python.exe -m projects.interview_trainer.profiles smoke strong
```

Модель задаётся профилем из `profiles.yaml`. Контракт у всех профилей один: `generate`, `generate_json` и `generate_choice`, лимит 1800 токенов контекста, одна рубрика M11 и одна политика обратной связи.
- **`tiny`** — Qwen2.5-0.5B-Instruct через transformers на CPU. Это профиль по умолчанию, тесты работают на нём.
- **`strong`** — Qwen3.5-4B Q4_K_M через llama-server из M09-L07X, рассуждения выключены, декодирование жадное. Если по адресу из профиля сервер не отвечает, тренажёр сам запускает `runtime/llama.cpp` с GGUF из `tools\download_models.py --gguf` и останавливает его при выходе. В Windows сервер привязан к процессу тренажёра и завершится, даже если закрыть окно. Число токенов считается до генерации через `/tokenize`, а выбор из ограниченного набора задаётся грамматикой из точных строк вариантов.
- **`ru-8b`** — русская модель на 8 млрд параметров через тот же сервер. Выключен: GGUF весит около 5 ГБ, и для загрузки нужно решение автора.
- **`api`** — любой совместимый с OpenAI платный endpoint, вне бесплатного пути курса. Выключен, пока в профиле не заданы `base_url` и `model`, а ключ не лежит в переменной окружения `TRAINER_API_KEY`. Вместо грамматики используется JSON Schema с перечислениями, лимит токенов проверяется после ответа.

Недоступный профиль не подменяется другим: тренажёр останавливается и пишет, чего не хватает. `/health` показывает активный профиль.

Авторская проверка 09.11.2026: одна и та же HR-реплика и одна backend-реплика прошли через рубрику на обоих профилях, файл `quality/profiles/smoke.json`. Оба профиля дали проверяемое наблюдение. `tiny` выбрал в HR-ответе личное действие, `strong` — обоснование. На одну реплику `strong` тратит около 5 с после запуска сервера за 8 с, `tiny` — 2–9 с, считая первую загрузку модели. Это проверка того, что профиль работает целиком, а не сравнение качества: сравнение моделей — отдельная задача T51.

## Поиск по базе вопросов (расширение 1.2.0)

```powershell
.\.venv\Scripts\python.exe -m projects.interview_trainer.question_rag search "как кандидат просит помощи"
.\.venv\Scripts\python.exe -m projects.interview_trainer.question_rag report
.\.venv\Scripts\python.exe -m projects.interview_trainer.question_rag evaluate
```

Интервьюер пишет тему своими словами и получает вопрос из `data/interview` вместе с тем, что искать в ответе, и уточнениями. В приложении тот же поиск отвечает на `GET /questions?q=...&k=3`. Полный режим собирает модули расширений M10: BM25 (T33), векторы USER-bge-m3 (T32) в файле sqlite-vec (T34), их слияние RRF и рерэнкер bge-reranker-v2-m3 по 10 лучшим кандидатам (T35). Без этих моделей тренажёр переходит в лексический режим (BM25 и символьный TF-IDF) и прямо пишет, что уверенность не оценивает. Флаг приложения `--questions full|lexical|auto`.

Авторская оценка 09.11.2026, `quality/question-search/report.json`: 40 запросов, написанных до первого прогона, по два на вопрос (с ключевым термином и пересказом без него), и 8 тем, которых в базе нет. Recall@1:
- поиск MCP-сервера из T42 по шести буквам — 0.650;
- символьный TF-IDF тренажёра — 0.650;
- USER-bge-m3 — 0.825;
- RRF BM25 и плотного поиска — 0.600: слияние со слабым BM25 без морфологии ухудшило плотный поиск;
- RRF и рерэнкер — 0.900, MRR 0.933.

На пересказах рост с 0.40 до 0.80, запросы с термином дают 1.0. Провалы T42 и T43 исправлены: «просит помощи» находит HR07, «сложная задача» — HR01. Отрицательный результат: вероятность рерэнкера на этой базе не отделяет темы вне базы от пересказов. Заранее выбранный порог 0.1 отклонил все 8 тем вне базы и 18 из 40 верных запросов. Поэтому поиск всегда показывает ближайшие вопросы и помечает уверенность, а решение остаётся за интервьюером. Загрузка двух моделей — 10 с, запрос — около 0.9 с, из них 0.84 с занимает рерэнкер.

## Безопасность: инъекция через данные, границы модели, журнал (расширение 1.2.0)

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests\test_trainer_security.py
.\.venv\Scripts\python.exe -m projects.interview_trainer.security_probe tiny
.\.venv\Scripts\python.exe -m projects.interview_trainer.app --trace-log artifacts\interview_trainer\trace.jsonl
```

В промпт попадают вопрос, найденные источники, ответ кандидата и история. Всё это данные. Отравленный вопрос из базы или источник — это косвенная инъекция. Защита в `security.py` и `feedback.py` устроена в три линии:
- **Входной фильтр T41.** Источник с признаком инъекции выбрасывается. Вопрос с таким признаком не отправляется модели: ход не засчитывается, и приложение прямо об этом пишет.
- **Экранирование.** Во всех данных `<` и `>` заменяются на `&lt;` и `&gt;`. И токенизатор transformers, и llama-server превращают текст `<|im_start|>` внутри сообщения в настоящий ролевой токен (находка T40). До исправления отравленный вопрос или источник добавлял к 5 ролевым токенам шаблона ещё 4: получался поддельный системный ход.
- **Граница вывода.** Инструментов у модели нет. Она выбирает один вариант из списка, который строит код, а на страницу попадают только постоянный текст рубрики и точная цитата кандидата. Ссылки источников показываются, только если это абсолютные http(s)-адреса: сервер очищает их, а страница проверяет ещё раз.

Журнал трасс (`--trace-log`, иначе в памяти) записывает каждый ход: вопрос, срабатывания правил на вопросе, источниках и ответе, выброшенные источники, вывод модели, статус проверки и политику показа. Ответ кандидата в журнал не попадает, только хеш и длина.

Авторская проверка 09.11.2026, `quality/trainer-security/`: 4 ответа, отравленный источник и отравленный вопрос приказывают выбрать другой фрагмент, критерий и следующий шаг, чем модель выбрала без отравления. Без фильтра поддельных ролевых токенов 0, на страницу ничего не попало. Но модель 4B выполнила приказ из данных в пределах разрешённых вариантов в 8 ходах из 8, модель 0.5B — в 2 из 8. Экранирование останавливает подделку ролей, но не убеждение. С фильтром 4 вопроса заблокированы, 6 источников выброшены, приказ не выполнен ни разу. У 4B выбор изменился в 2 ходах, где выбросили оба источника и модель отвечала без справки. Фильтр работает по шаблонам и пропускает пересказанный приказ без маркеров: на этот случай остаётся граница вывода, и тест это показывает.

## Как проверять результат

1. Пройди один HR и один backend сценарий. Сохрани JSON в submissions, а время каждого хода перенеси в отчёт.
2. Для HR отдельно оцени конкретность, личный вклад, обоснование и результат. Для backend — техническую правильность, полноту, компромиссы и подтверждение источниками. Рубрики и примеры находятся в материалах M11/M16 и data/interview. Разные сценарии не получают общий числовой балл.
3. Сверь утверждения модели с ответом кандидата и источником. Наличие ссылки в интерфейсе означает, что документ найден, а не что каждое предложение модели им подтверждено. У маленькой модели возможны слабый русский язык, повторы, неверные замечания и обрыв на лимите токенов.
4. Запиши свою фразу и вручную подготовь расшифровку. Вычисли WER. Сравни тишину и бытовой шум, разные длины реплик. Прогон SAPI→Vosk проверяет техническую связность, но не качество микрофона или реальных людей.
5. Проверь двойную отправку, слишком длинный ответ, запрещённый режим, устаревший номер хода, пустое аудио, отмену во время синтеза и завершённую сессию.

Команда содержательных проверок состояния и границ:

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_interview_trainer.py -q
.\.venv\Scripts\python.exe labs\M15\demo.py
```

Расширение 1.2.0: регрессию prompt оценки на двух профилях моделей, tiny (Qwen2.5-0.5B) и strong (Qwen3.5-4B), можно гонять через promptfoo. Конфиг лежит в `labs/M11/promptfoo`, инструкция — в разделе о promptfoo урока M11-L06; нужен Node.js. Основными остаются проверки pytest выше.

## Границы эталона и самостоятельное улучшение

Эталон демонстрирует последовательную цепочку и ограниченные уточнения. Короткая база, эвристика полноты ответа и маленькая LLM не доказывают качество полноценного интервьюера. Нет автоматического barge-in, долговременного хранилища сессий, одновременного обслуживания пользователей и production-аутентификации. Он не предназначен для публичного размещения без переработки. Новая самостоятельная M16 требует запускаемый собственный вариант и сохранение состояния между процессами; ключ атомарного хранения находится в solutions/exercises/M16/persistence.py. Запуск эталона не засчитывает эту работу.

Микрофон зависит от разрешения Edge и выбранного устройства. Если разрешение отклонено, поле текста остаётся рабочим, а качество голоса помечается «не проверено». Линейное изменение частоты в клиенте — понятный учебный baseline: для промышленного аудио сравни его с фильтрующим ресемплером на шумных записях. Установленный русский голос проверен как `Microsoft Irina Desktop`; на другом Windows сначала проверь его наличие.

Источники реализации: [карточка Qwen](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct), [Vosk: модели](https://alphacephei.com/vosk/models), [System.Speech](https://learn.microsoft.com/en-us/dotnet/api/system.speech.synthesis.speechsynthesizer), [AudioWorklet](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet), [HTTP semantics](https://www.rfc-editor.org/rfc/rfc9110.html), [индексы PostgreSQL](https://www.postgresql.org/docs/current/indexes-intro.html).

## Наблюдавшиеся ошибки исходной свободной генерации 1.0.0

В техническом прогоне на этом ноутбуке холодная генерация 128 токенов заняла около 55 секунд вместе с загрузкой. Другой прогон при параллельной подготовке курса и дефиците свободной RAM занял около 128 секунд; это показывает зависимость от загрузки устройства. В SQL-разборе модель начала перечисление, затем оборвалась на слове из-за лимита. В HR-прогоне она переписала ответ от первого лица и добавила неподтверждённый результат «API оплаты успешно запущен». Это наблюдения на двух искусственных ответах, не статистическая оценка.

Проверь их по M11: неподтверждённое утверждение — ошибка даже при уверенной формулировке; обрыв — отдельная проблема завершённости. Клиент показывает достижение лимита. Улучшение prompt, ограничение формата, более подходящая модель и отклонение непроверяемых советов сравниваются на отдельном наборе. Увеличение max_new_tokens может исправить обрыв, но увеличит задержку и не гарантирует правильности.
