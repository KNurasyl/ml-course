# Эталон: локальный голосовой тренажёр

Это отдельная учебная реализация для разбора после собственной попытки M16. В ней есть два сценария по четыре вопроса: HR и backend. Вопросы и переходы задаёт Python, обратную связь генерирует настоящая небольшая Qwen2.5-0.5B-Instruct на CPU. Технический сценарий добавляет в контекст результаты простого лексического поиска. Vosk распознаёт речь, Windows SAPI озвучивает вопросы. Платные API не используются.

## Запуск

Из папки курса в PowerShell:

```powershell
Set-Location C:\projects\ml-llm-course
.\.venv\Scripts\python.exe tools\download_models.py --speech --llm
.\.venv\Scripts\python.exe -m projects.interview_trainer.app
```

Открой http://127.0.0.1:8765 в Edge. Выбери направление, нажми «Начать интервью». «Озвучить вопрос» запускает местный русский голос. «Записать голос» просит доступ к микрофону; «Закончить запись» отправляет WAV в локальный распознаватель. Сначала проверь распознанный текст, затем отправь ответ. Можно вводить ответ с клавиатуры. «Прервать голос» останавливает воспроизведение и игнорирует результат ещё не завершённого запроса синтеза. Первый ответ загружает LLM, поэтому его время включает холодный старт.

Скачивание нужно один раз; на этом ноутбуке модели уже загружены. LLM занимает около 1 ГБ на диске, речь — десятки МБ; дополнительная M09 использует отдельную модель. Версии моделей зафиксированы в [reference-models.json](../../metadata/reference-models.json). После установки и скачивания сервер работает без сети. Исходные ссылки используются только при открытии источников человеком. Для восстановления Python-окружения: `tools/bootstrap.ps1`.

Выход: Ctrl+C в окне PowerShell. Сервер слушает только 127.0.0.1. Порт можно изменить `--port 8766`. При сообщении о занятом порте не останавливай незнакомый процесс: выбери другой порт.

## Что происходит в запросе

```text
Микрофон → PCM WAV → Vosk → редактируемый текст
                                     ↓
Состояние интервью → вопрос → поиск → контекст → Qwen → обратная связь
                    ↓
               Windows SAPI → WAV → воспроизведение / отмена
```

В `core.py` живут сценарии, проверка номера хода и поиск. `llm.py` загружает pinned snapshot локально и ограничивает вход 1800 токенами, выход 128 токенами. `speech.py` проверяет mono PCM16 16 kHz. `app.py` соединяет их через HTTP. Одновременно выполняется одна тяжёлая операция: второй запрос получает явную ошибку 409. `web/` содержит браузерный клиент, запись через AudioWorklet, преобразование в WAV и отмену воспроизведения. AudioWorklet захватывает поток, однако распознавание и генерация выполняются после целой реплики; потоковый ASR/LLM — самостоятельное расширение M15.

Ответы хранятся в памяти процесса. Кнопка экспорта сохраняет сессию JSON по действию пользователя; перезапуск сервера удаляет несохранённые сессии. Идентификатор текущей сессии хранится в sessionStorage вкладки; «Восстановить сессию» получает актуальное состояние после потери HTTP-ответа или обновления вкладки. Эта кнопка не восстанавливает данные после перезапуска сервера. Временные WAV удаляются после распознавания или отправки синтеза. Консоль не печатает содержание интервью. Не отправляй личные сведения, которые не нужны для учебной задачи.

## Как проверять результат

1. Пройди один HR и один backend сценарий. Сохрани JSON в submissions, а время каждого хода перенеси в отчёт.
2. Для HR отдельно оцени конкретность, личный вклад, обоснование и результат. Для backend — техническую правильность, полноту, компромиссы и подтверждение источниками. Рубрики и примеры находятся в материалах M11/M16 и data/interview. Разные сценарии не получают общий числовой балл.
3. Сверь утверждения модели с ответом кандидата и источником. Наличие ссылки в интерфейсе означает, что документ найден, а не что каждое предложение модели им подтверждено. У маленькой модели возможны слабый русский язык, повторы, неверные замечания и обрыв на лимите токенов.
4. Запиши свою фразу и вручную подготовь расшифровку. Вычисли WER. Сравни тишину и бытовой шум, разные длины реплик. Прогон SAPI→Vosk проверяет техническую связность, но не качество микрофона или реальных людей.
5. Проверь двойную отправку, слишком длинный ответ, запрещённый режим, устаревший номер хода, пустое аудио, отмену во время синтеза и завершённую сессию.

Команда содержательных проверок состояния и границ:

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_interview_trainer.py -q
.\.venv\Scripts\python.exe labs\M15\demo.py
```

## Границы эталона и самостоятельное улучшение

Эталон демонстрирует работающую последовательную цепочку. Его 4 вопроса, короткая база знаний, ограниченная LLM и лексический baseline не доказывают качество полноценного интервьюера. Нет автоматического барж-ина по VAD, долговременного хранилища сессий, одновременного обслуживания пользователей и production-аутентификации. Он не предназначен для публичного размещения без переработки этих частей. Самостоятельная M16 требует обосновать объём продукта, измерить ограничения и защитить решения; запуск эталона не засчитывает её.

Микрофон зависит от разрешения Edge и выбранного устройства. Если разрешение отклонено, поле текста остаётся рабочим, а качество голоса помечается «не проверено». Линейное изменение частоты в клиенте — понятный учебный baseline: для промышленного аудио сравни его с фильтрующим ресемплером на шумных записях. Установленный русский голос проверен как `Microsoft Irina Desktop`; на другом Windows сначала проверь его наличие.

Источники реализации: [карточка Qwen](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct), [Vosk: модели](https://alphacephei.com/vosk/models), [System.Speech](https://learn.microsoft.com/en-us/dotnet/api/system.speech.synthesis.speechsynthesizer), [AudioWorklet](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet), [HTTP semantics](https://www.rfc-editor.org/rfc/rfc9110.html), [индексы PostgreSQL](https://www.postgresql.org/docs/current/indexes-intro.html).

## Наблюдавшиеся ошибки модели

В техническом прогоне на этом ноутбуке холодная генерация 128 токенов заняла около 55 секунд вместе с загрузкой. Другой прогон при параллельной подготовке курса и дефиците свободной RAM занял около 128 секунд; это показывает зависимость от загрузки устройства. В SQL-разборе модель начала перечисление, затем оборвалась на слове из-за лимита. В HR-прогоне она переписала ответ от первого лица и добавила неподтверждённый результат «API оплаты успешно запущен». Это наблюдения на двух искусственных ответах, не статистическая оценка.

Проверь их по M11: неподтверждённое утверждение — ошибка даже при уверенной формулировке; обрыв — отдельная проблема завершённости. Клиент показывает достижение лимита. Улучшение prompt, ограничение формата, более подходящая модель и отклонение непроверяемых советов сравниваются на отдельном наборе. Увеличение max_new_tokens может исправить обрыв, но увеличит задержку и не гарантирует правильности.
