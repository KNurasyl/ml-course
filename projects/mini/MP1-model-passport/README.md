# MP1 «Паспорт моделей»

**Уровень 1 маршрута 2.0.** Мини-проект завершает уровень «Модели и запуск». Тьютор делит его на занятия по 30–45 минут: запуск и замер, качество, вывод.

## Задача

Компания «Лампа и Чайник» (вымышленная, `data/company/`) хочет ИИ-оператора, который разбирает обращение клиента в JSON: категория, номер заказа, срочность. Выбери модель для этого оператора на своём ноутбуке. Для этого сравни три конфигурации на одних и тех же 20 запросах и составь «паспорт»: сколько памяти занимает конфигурация, как быстро отвечает, насколько надёжно выдаёт JSON и насколько верно разбирает запросы.

Конфигурации:

1. Qwen2.5-0.5B Q4_K_M на CPU;
2. Qwen3.5-4B Q4_K_M на GPU (модель занятий по замеру R06);
3. русская модель на 8 млрд параметров (профиль `ru-8b`) — по решению автора её скачивают на этом уровне, около 5 ГБ, только после подтверждения автора. Пока её нет, третьей конфигурацией бери 4B на CPU и отметь это в выводе.

Основа — инструменты T51 (`projects/interview_trainer/compare_profiles.py`) и замер R06 (`quality/hardware/README.md`). Новое здесь — сравнение CPU против GPU и разбор запросов в JSON.

## Данные

- `data/company/operator_requests.jsonl` — 20 запросов с ожидаемыми полями `expected` (категория, номер заказа, срочность). Эталон открывай только для подсчёта качества, не для настройки промпта.
- Категории: `delivery_delay`, `return_request`, `warranty_repair`, `payment_issue`, `installation`, `product_question`, `order_change`, `complaint_other`; срочность: `low`, `medium`, `high`.

## Как начать

```powershell
.\.venv\Scripts\python.exe projects\mini\MP1-model-passport\starter.py --config qwen2.5-0.5b-cpu
```

Стартер запускает llama-server, отправляет 20 запросов и сохраняет сырые ответы и замеры в `submissions/MP1/passport.json`. Системный промпт, разбор JSON, рубрику качества и вывод пишешь сам: места помечены `TODO`.

## Критерии приёмки

Файл `submissions/MP1/passport.json` проверяет `check.py`:

```powershell
.\.venv\Scripts\python.exe projects\mini\MP1-model-passport\check.py
```

1. Не меньше трёх конфигураций. У каждой по одному ответу на каждый из 20 запросов.
2. По каждой конфигурации указаны память RAM (МиБ), видеопамять (для GPU), медиана времени до первого токена и медиана токенов в секунду.
3. Доля валидного JSON пересчитывается из сырых ответов и совпадает с указанной. Валиден объект с полями `category`, `order_id`, `urgency`.
4. Качество по рубрике: каждый ответ оценён 0, 1 или 2, рубрика записана в поле `rubric`, среднее совпадает. Отдельно — доля верных категорий против `expected`.
5. Вывод «какую беру и почему» — не меньше 40 слов, названа выбранная конфигурация, указана цена выбора: память, скорость или качество.

Проверка не ставит оценку: она сверяет структуру и пересчитывает числа. Почему выбор верен, спросит тьютор.
