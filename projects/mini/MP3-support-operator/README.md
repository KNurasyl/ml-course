# MP3 «Оператор поддержки»

**Уровень 3 маршрута 2.0.** Первый публичный кейс портфолио (уровень 7). Набор проверок — твой MP2.

## Задача

Собери ИИ-оператора поддержки «Лампа и Чайник» по базе знаний `data/company/kb/` (42 документа). Оператор находит нужные документы, отвечает по ним со ссылкой на источник `[KB-xxx]` и отказывается, когда в базе ответа нет: «В базе знаний нет ответа, передаю вопрос специалисту». Затем улучши его и покажи на наборе MP2, что стало лучше, а что нет.

Модель — `session_model` из `course/route-v2.yaml` (4B на GPU) через llama-server; запасной вариант — та же модель на CPU. Поиск — на твой выбор из уровня 3: BM25, векторный, гибридный (M10).

## Что сдать (в `submissions/MP3/`)

| Файл | Содержимое |
| --- | --- |
| `runs/baseline.jsonl` | ответ первой версии на каждый случай MP2: `case_id`, `answer`, `cited` (список KB-xxx), `refused` (true/false), `retrieved` (найденные KB-xxx) |
| `runs/improved.jsonl` | то же после улучшений |
| `metrics.json` | метрики обеих версий (см. ниже) и `changes` — что именно изменено между версиями |
| код оператора | любые файлы; стартер — `starter.py` |

Метрики считает `check.py` из файлов прогонов, ты записываешь их в `metrics.json` своим кодом, и они должны совпасть:

- `citation_valid` — доля ответов, где все `cited` существуют в базе;
- `source_hit` — доля случаев с ответом, где среди `cited` есть хотя бы один `expected_sources` случая;
- `refusal_recall` — доля случаев без ответа, где оператор отказался;
- `false_refusal` — доля случаев с ответом, где оператор отказался;
- `retrieval_recall` — доля случаев с ответом, где среди `retrieved` есть ожидаемый источник.

## Критерии приёмки

```powershell
.\.venv\Scripts\python.exe projects\mini\MP3-support-operator\check.py
```

1. Набор MP2 на месте: не меньше 40 случаев, из них не меньше 8 без ответа (полностью его проверяет `check.py` MP2).
2. Оба прогона покрывают все случаи MP2.
3. Метрики в `metrics.json` совпадают с пересчётом для обеих версий.
4. Каждая ссылка в ответах существует в базе (`citation_valid` = 1.0 в улучшенной версии).
5. `changes` описывает изменения (от 20 слов), а отрицательный сдвиг какой-либо метрики не скрыт: если метрика упала, в `changes` есть её имя.

Ответ «стало лучше» без чисел до и после не засчитывается. Падение метрики — тоже результат, его записывают, а не прячут (инвариант И6).
