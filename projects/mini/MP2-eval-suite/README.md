# MP2 «Набор проверок для оператора»

**Уровень 2 маршрута 2.0.** Набор, который ты соберёшь здесь, станет мерилом для MP3: по нему будет видно, стал ли оператор лучше.

## Задача

Собери набор проверок для ИИ-оператора поддержки компании «Лампа и Чайник» (`data/company/kb/`, 42 документа). Оператор отвечает клиенту по базе знаний и ссылается на документ. Если ответа в базе нет, оператор должен честно сказать об этом и передать вопрос человеку. Нужен набор, который ловит обе беды: выдуманный ответ и лишний отказ.

## Что сдать (в `submissions/MP2/`)

| Файл | Содержимое |
| --- | --- |
| `cases.jsonl` | 40 случаев и больше: `id`, `question`, `answerable` (true/false), `expected_sources` (KB-xxx; пусто, если ответа нет), `expected_facts` (что обязано быть в ответе) |
| `rubric.md` | Рубрика ответа: не меньше трёх критериев, у каждого шкала и пример. Обязательно отдельный критерий «отказ, когда ответа нет» |
| `annotations.jsonl` | Не меньше 20 ответов оператора (любой модели), каждый оценён тобой (`manual`) и автоматической оценкой (`auto`: модель-судья или правило) по одной шкале |
| `agreement.json` | `{"kappa": ..., "n": ...}` — согласие автоматической оценки с ручной (каппа Коэна) и что ты из него выводишь (`note`) |
| `test_regression.py` | pytest-тесты, которые прогоняют набор и падают, если доля верных отказов или доля ответов с верным источником опустились ниже порога |

Не меньше 8 случаев — без ответа в базе: вопрос по теме магазина, но факта нет ни в одном документе (например, о доставке за границу или о товаре, которого нет в каталоге). Ещё 4–5 случаев проверяют попытку увести оператора от инструкций.

Шаблоны с тремя примерами — в `templates/`. Скопируй их в `submissions/MP2/` и продолжай.

## Критерии приёмки

```powershell
.\.venv\Scripts\python.exe projects\mini\MP2-eval-suite\check.py
```

1. Не меньше 40 случаев с уникальными `id`; не меньше 8 с `answerable: false`.
2. Каждый `expected_sources` существует в базе знаний; у случаев с ответом есть хотя бы один источник и хотя бы один ожидаемый факт.
3. В рубрике не меньше трёх критериев, один из них про отказ.
4. Не меньше 20 размеченных ответов; каппа в `agreement.json` совпадает с пересчётом.
5. `test_regression.py` содержит не меньше двух тестов, один из них — порог доли верных отказов или верных источников, и проходит на твоём наборе (`pytest submissions/MP2/test_regression.py`).
6. В `agreement.json` записан вывод (`note`, от 10 слов): можно ли доверять автоматической оценке и где нет.
